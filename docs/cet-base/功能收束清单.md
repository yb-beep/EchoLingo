## 0. 收束机制（先看这一节，后面所有条目都靠它）

三条硬规则，全部在代码里可验证：

1. **单一开关源**：所有判断都读 `cet_mode` 的同一份配置。模板用 `{% if cet_features.X %}`，
   前端用 `CET.feature('X')`（`frontend/static/cet-mode.js:86`）。
   模板里**没有**第二套 `if cetMode` 之类的写死开关。
2. **退出 = 不渲染**，不是 CSS 遮挡。收束的区块被 Jinja 包住，CET 模式下**根本不在 DOM**，
   所以不会被 Tab 聚焦、不会发后台请求。
3. **收束的模块不初始化**。`frontend/templates/index.html:8493-8516` 的 Init 块按功能键逐项判断，
   未启用的模块连初始化函数都不调用。

`ELT_CET_MODE=0` 退回通用模式：全部入口恢复（原版回归用）。本板块所有收束判断都有对应的
`{% else %}` / `if (!CET.enabled())` 分支，`tests/test_cet_base_mode.py` 与
`tests/test_cet_base_home.py` 双向验证两种模式。

## 八、已知限制（如实记录）

1. **`/api/cet/base/*` 不在本板块工作树**：本板块基于 `fc96a63`，该路由由「材料与导入」板块实现、
   Lead 合并。因此本板块的浏览器证据走的是**降级链路**（`/api/v2/lessons/library` 读材料库、
   `/api/v2/lessons/media-uploads` + `/api/v2/lessons/start` + `PATCH .../library/{id}` 导入）。
   降级路径字段与 `cet_base` 契约对齐，Lead 合并后主路径自动生效。
2. **年份/月份/套次/题型不落库**：只显示「未标注」（Lead 定案，见 §1.3）。若要支持用户填写，
   需新增 schema 列并走评审，不在本轮范围。
3. **情境造句 / 泛用 AI 聊天 / 大纲生成**：本板块 `index.html` 无独立入口（在工作区/精读页），
   只由 `cet_mode` 收束；这两个页面的实际渲染收束由「播放与收藏」板块负责。
4. **`/planning`、`/login`、`/account` 整页路由**：公开库本就没有对应模板（`pages.py` 条件注册），
   访问会 404。CET 模式下页面内已无指向它们的链接，但直接输 URL 仍会 404 —— 这是原有行为，
   本板块不改后端路由注册（不在权限范围）。
