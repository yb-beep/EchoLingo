**句循环实现**（任务书未规定细节，包2 的实现选择，供审核方复核）：
- 判定 `now >= end - LOOP_EPSILON(0.02s)` → `seekToSeconds(start)`，走 `__ws.seek()`（页面唯一实现）
- **锚点快照** `S.loopAnchor={index,start,end}`，不用 `activeSentenceIndex`（越过句尾那刻它已指向下一句）
- 双驱动源：rAF 逐帧（主，误差 ~16ms）+ `timeupdate`（兜底，后台标签页 rAF 会停；只靠它会多播 250ms）
- 回跳后 260ms 静默窗（`loopGuardUntil`），防 seek 触发的 `timeupdate` 反复 seek
- 无逐句时间轴时按 L 直接回退，不给假承诺

**顺带修的真 bug**（对其它包也适用，已转告包1/包5）：
`cet-workspace.css:60` 的 `.cet-study-item { display: inline-flex }` 是作者样式，优先级高于 UA 的 `[hidden] { display:none }`，
所以 `el.hidden = true` 元素**照样显示**。包2 新增 `setShown(el, show)`（`cet-player.js:689`）同时设 `hidden` 与行内 `display`。

## 4. 与任务书字面要求的有意偏离（如实记录）

### 4.1 P1-6 / P4-3：`natural-tts.js` 在 CET 模式**保留加载**

**任务书 §2 P1-6 字面要求**：「CET 模式页面无这三个 `<script>`；通用模式仍有」。
**实际实现**：`elt_credits.js` ✅ 无、`voice-input.js` ✅ 无、**`natural-tts.js` 有**。

**理由**（主代理裁决，已核实源码）：
`natural-tts.js` 在 CET 页面是**被保留功能直接使用**的，不是只服务已收束模块：
- `index.html:7150 speakWord` —— 收藏词卡 🔊 发音（P4-1 验收要求「带原句和回到原句」，发音是同一张卡上的操作）
- `index.html:5422 / 5779` —— 句子收藏兜底朗读
- `index.html:5856` —— 词汇例句朗读
- `workspace.html:4514-4517` —— 工作区朗读

P1-6 的规则原文是「**按对应 feature 条件加载**」，不是「删掉」。`natural-tts` 服务的
`word_favorites` 与 `sentence_favorites` 两个 feature CET 都 `kept=True`，所以条件加载后 CET 默认仍输出 ——
**这符合「按对应 feature 条件加载」的本意**。硬移除会导致 CET 下单词发音与句子兜底朗读直接失效（功能回归）。

**为什么不新增 `natural_tts` feature key**：`tests/test_cet_base_mode.py:30-54` 的 `KEPT_FEATURES` 是**冻结集合**，
第 54 行是精确相等断言（注释原文「拼错会 KeyError，这是故意的」）。为一个朗读脚本动冻结契约，代价与收益不匹配。
故挂在已有 key `word_favorites or sentence_favorites` 上。

**审核方复验建议**：若认为必须严格按字面执行，改 `{% if %}` 条件即可（`workspace.html:1935`、`index.html:2488-2502`），
但需接受 CET 下单词发音失效。

### 4.2 P4-2：CTA 文案用「继续自评熟悉度 →」而非「继续词汇练习 →」

**任务书 §2 P4-2** 举例「继续词汇练习 →」。**实际实现** CET 为「继续自评熟悉度 →」。

**理由**：该页真实动作是自评熟悉度三级（不认识 / 模糊 / 认识），页面上**没有「练习」入口**，
写「练习」会指向不存在的功能。任务书该条的核心要求是「改为中文四六级口径（**经 `cet_copy` 取，别写死**）」，
不是逐字照抄示例。通用模式仍保留原文「继续词汇练习 →」。

### 4.3 P3-1：未走任务书提示的 `start_local_lesson(transcript_path=...)` 路径

**任务书 §2 P3-1** 提示「有原文 TXT 时优先走原版文本对齐路径（`v2_lessons.start_local_lesson(transcript_path=...)`）」。
**实际实现**：改为「原文句子 → 词级时间戳投影」自己实现。

**理由**：包3 实测 `parse_subtitle_file` 只认 SRT/VTT 的 `-->` 行，**喂纯文本返回 `[]`** ——
照抄该路径会得到空时间轴、静默失败。这是任务书提示本身的错误，不是实现偷懒。
理由写在 `docs/cet-base/导入与材料.md` §3.10。

### 5.4 `cet-workspace.css:60` 的 CSS 优先级坑

**现象**：`.cet-study-item { display: inline-flex }` 压过 UA 的 `[hidden] { display:none }`，

**影响**：**既有**功能 —— 任何只设 `hidden` 的地方在 CET 下都可能失效（不是返修2 引入）。
**返修2 内的规避**：包2 新增 `setShown()` 同时设行内 `display`；包1 用 Jinja 条件 + `el.remove()`。
**未修理由**：修 CSS 会影响所有 `.cet-study-item` 的使用点，超出返修2 范围。
**建议**：下一轮给 `.cet-study-item[hidden] { display: none !important; }` 或统一走 `setShown`。

### 5.5 `sentence_units > segments` 的通用现象

`cet4-sample-hope-wish` 实测 `segments=32 / sentence_units=35`（本身无说话人标记）。
这是 `v2_translation.build_translation_units()` 既有的「一条 cue 内含多句按标点再切」行为，**不是缺陷**。
**报告口径**：句子数请以 **`segments`** 为准，`sentence_units` 是播放单元数。
