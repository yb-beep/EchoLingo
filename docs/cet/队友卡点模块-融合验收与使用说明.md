## 1. 结论：功能完整度

**实测结论：卡点模块的主线功能是完整的**，不存在「半成品」缺口。

| 功能块 | 状态 | 说明 |
| --- | --- | --- |
| 材料 / 题目 | ✅ 完整 | 5 题/材料，选项可点 |
| 交卷 | ✅ 完整 | 必须带 `listeningSessionId`（见 §3.1） |
| 卡点标记 | ✅ 完整 | 建 → 吸附候选句 → 预览 → 确认 / 改一下 / 删除 |
| 带练 | ✅ 完整 | 开带练 → 反馈（没听清/不懂意思/听懂了）→ 保存本轮 |
| 复习 | ✅ 完整 | 今日复习 → 回听/跳过/这处练完了/暂停/结束复习 |
| 刷新恢复 | ✅ 完整 | 标记、交卷结果、带练、复习会话都能恢复 |
| AI 增强 | ⚠️ 无 key 时降级 | 无 `AI_API_KEY` 时「不懂意思」返回 503 `AI_NOT_CONFIGURED`，其余功能不受影响 |

**主代理之前误判的两处**（记录在此避免后人重蹈）：

1. **「复习链路是断的」** —— 错。`cet_review_items` 只在 `finish_practice()` 时生成，
   我当时直接调 `POST /reviews` 而没有先 finish，所以拿到 `NO_REVIEW_ITEMS`。
2. **「练习面板没挂载」** —— 错。`renderPractice()` 只在有 `S.practice` 时建 DOM，
   而 `S.practice` 由 UI 点「开始带练」后 `save()` 持久化。我当时用 API 直接建带练、绕过了前端 `save()`，
   刷新后自然恢复不出来。

## 3. 接口契约（实测确认，非文档推断）

**以下契约全部由主代理在真实服务上验证过**。队友原文档 `docs/cet/接口契约-权威版.md` 是 11-05 的，
早于本轮改动；以本节为准。

### 3.1 交卷 `POST /api/cet/attempts`

```json
{
  "materialId": "cet6-202512-conv2",
  "materialVersion": "sha256-...",
  "listeningSessionId": "cet-session-xxx",   // ★ 必填，否则 422
  "answers": [{"questionId": "q-05", "answer": "A"}]
}
```

- **`listeningSessionId` 必填**：只传 `answers` 会 422 `ATTEMPT_ID_REQUIRED`（"materialId 和 listeningSessionId 不能为空"）
- 幂等靠 `listeningSessionId`：同一材料同一会话只交一次卷；重复交卷且**答案不同**会 409
- 题目 `options` 是**字符串数组**（不是 `{key, text}` 对象），答案按 `"A"/"B"/"C"/"D"` 传

### 3.2 建标记 `POST /api/cet/marks`

```json
{
  "materialId": "...", "materialVersion": "...",
  "listeningSessionId": "...",
  "pressedAtSec": 10.0,          // 按下时刻
  "reactionDelaySeconds": 2.5,   // 回溯窗口（前端 CFG.lookbackSec）
  "speed": 1.0                   // 实际播放倍速
}
```

- 后端用 `adjusted = pressedAtSec - reactionDelaySeconds * speed` 去吸附候选句
- **不传 `reactionDelaySeconds` / `speed` 会用默认 0.6 / 1.0**，前端的 2.5s 回溯就失效
- 返回含 `suggestedSentenceId`（建议句，尚未确认）

### 3.3 确认句 `PATCH /api/cet/marks/{mark_id}`

```json
{"confirmedSentenceId": "v2-1-2"}
```

- **必须先交卷**，否则 409 `ATTEMPT_REQUIRED`（"请先交卷，再确认卡点句子"）

### 3.4 删除标记 `DELETE /api/cet/marks/{mark_id}`（本轮队友新增）

- 成功：`{"deleted": true, "markId": "..."}`
- 不存在：404 `MARK_NOT_FOUND`
- **已开始带练**：409 `MARK_IN_PRACTICE`（"该标记已开始带练，不能删除"）—— 保护练习记录

前端按钮：`cet-listening.js` 的 `renderMarks()` 里，样式 `.cet-btn-sm.cet-btn-danger`（浅红危险色）。

### 3.5 开带练 `POST /api/cet/practices`

```json
{"markId": "...", "materialId": "...", "materialVersion": "...", "sentenceId": "v2-1-2"}
```

返回含 `practiceId`、`currentStepId`、`currentStep`、`status`。

### 3.6 带练推进 `POST /api/cet/practices/{id}/next`

```json
{"stepId": "<当前 currentStepId>", "materialVersion": "...", "feedback": "sound"}
```

- **`feedback` 是语义驱动参数**，取值 `sound`（没听清）/ `meaning`（不懂意思）/ `heard`（听懂了）
- 服务端据此选动作（`replay` / `slow` / `chunk` / `explain` / `transfer`）
- **不传 `feedback` 也能返回 200，但只是空转**（不会推进语义）—— 这是最容易误判成「坏了」的地方
- **`stepId` 每次推进后都会变**，必须用**上一次响应返回的** `currentStepId`，不能复用旧值
- 无 AI key 时 `feedback=meaning` 返回 503 `AI_NOT_CONFIGURED`（提示"仍可使用本地回听、慢放、原文和保存"）

### 3.7 结束带练 `POST /api/cet/practices/{id}/finish`

```json
{"stepId": "<最新 currentStepId>", "materialVersion": "..."}
```

- **这一步才生成 `cet_review_items`** —— 不 finish 就没有复习条目
- 成功后返回 `reviewItem`（含 `sentence`、`audioUrl`）

### 3.8 复习清单 `GET /api/cet/review-items`

返回所有 `review_items`（JOIN `cet_practices` 取句子与音频）。`status='pending'` 的才是待复习。

### 3.9 建复习 `POST /api/cet/reviews`

```json
{"maxItems": 3}
```

- **只取 `status='pending'` 的条目**（按 priority / updated_at 排序，最多 3 条）
- 没有 pending 条目 → 409 `NO_REVIEW_ITEMS`
- 指定条目用 `{"itemIds": [...]}`（最多 3 项，且必须都是 `pending`，否则 409 `REVIEW_ITEM_UNAVAILABLE`）
- 新建的会话是 `ready` 状态，**skip/complete 需要先 `start`**（前端 `startReview()` 已自动处理）

### 3.10 复习动作 `POST /api/cet/reviews/{id}/actions`

```json
{"action": "start", "actionId": "aid-xxx", "entryId": "...", "itemId": "..."}
```

- **`actionId` 必填**，否则 422 `INVALID_REVIEW_ACTION`
- 合法 action：`start` / `pause` / `resume` / `skip` / `replace` / `complete` / `finish`
  （别名：`begin`→`start`，`continue`→`resume`）
- 条目状态流转：`current` → `done`

## 4. 前端状态持久化

`cet-listening.js` 用 localStorage 两个键：

| 键 | 内容 | 说明 |
| --- | --- | --- |
| `cet.session.v1` | sessionId | **每个浏览器会话独立**。换无痕窗口/清站点数据会生成新 ID，旧标记按新会话查不到（数据还在库里） |
| `cet.state.v2.<materialId>` | `{materialId, attemptId, practiceId, reviewId}` | 按材料分键，避免四级页面恢复出六级的成绩 |

`save()` 在以下时机调用：建标记、确认、开带练、带练反馈、finish、复习动作。

**关键**：`practiceId` / `reviewId` 只有**通过 UI 操作**才会写入。用 API 直接建带练、再刷新页面，
前端恢复不出来（它不知道有这个 practice）—— 这不是缺陷，是「状态由前端自己维护」的设计。

## 5. 已知限制

| 限制 | 影响 | 处理 |
| --- | --- | --- |
| 无 AI key 时 `feedback=meaning` 返回 503 | 「不懂意思」这条反馈路径不可用 | 其余反馈与本地回听/慢放/原文/保存均可用；配 key 后自动恢复 |
| `sessionId` 按浏览器会话隔离 | 换设备/无痕窗口看不到旧标记 | 数据仍在库中（`cet_marks`），换回原会话或清 localStorage 前可查 |
| 标记需先交卷才能确认 | 未交卷时点「确认这句」409 | 前端会提示「请先交卷，再确认卡点句子」 |
| 复习只取 `pending` 条目 | 条目被 `done` 后不再出现在新会话 | 属正常语义（练过就不再排） |

## 6. 实测记录（2026-11-07，端口 5173）

### 6.1 完整链路（API 层）

```
交卷 201 → 建标记 201 → 确认 200 → 开带练 201 → next(feedback) 200 → finish 200 → review-items 1 条
```

### 6.2 完整链路（UI 层，真实点击）

```
题目面板：选项可点 ✅
标记列表：「卡点标记（1）| 1:05.33 | 待确认 | ... | 回听 | 前一句 | 后一句 | 确认这句 | 删除」
点「确认这句」→ ✅
点「开始带练」→ 带练面板出现：「卡点带练 | 没听清 | 不懂意思 | 听懂了 | 当前步骤：原句回放 | 保存本轮」
点「没听清」→ 「反馈「没听清」→ 慢放」✅
点「今日复习」→ 201 + 200，面板：「进行中 · 剩余约 10 分钟 · 第 1 处」
             按钮：回听 / 跳过 / 这处练完了 / 暂停 / 结束复习 ✅
点「跳过」→ 200，会话状态转「已结束」✅
JS 报错：无
```

### 6.3 刷新恢复

```
刷新后：标记恢复 ✅  交卷结果恢复 ✅  带练面板恢复 ✅  复习会话恢复 ✅
```
