## 0. 这份文档上一版错在哪里（必须先读）

验收报告 D03 指出：上一版权威契约**只允许三种播放事件**，并要求
「其他类型一律 422」。如果机械执行，会直接删掉前端依赖的
`visibility`（后台计时）与 `transfer_answer`（换句作答）——
**这不是统一契约，是破坏功能。**

本版按冻结约定修正为**七种事件**，并把「哪些是播放事件、哪些是业务事件」
分开表述。同时修正三处事实性错误：

| 上一版写法 | 问题 | 本版 |
| --- | --- | --- |
| 事件只有三种 | 删了前端依赖项 | 七种，短名为别名 |
| 「其他一律 422」含短名 | Mock/真实后端都接受短名 | 短名是合法别名 |
| 用受控模型「33/39 与无 key 一致」论证不缺 key | **受控 fixture 非法，成功路径从未跑通** | 已重做 D02，见 §12 |

关于最后一条的证据：上一版受控 fixture 固定返回两个跨句短语
（`displaying signs of weariness` / `call it a day`），而生产校验器要求
短语是**当前原句的连续子串**，于是 32 句全部 `AI_INVALID_OUTPUT`。
所以那个「一致」是两种失败的重合，不能作为结论依据。

## 1. 通用约定

| 项 | 规定 |
| --- | --- |
| 时间轴字段 | 绝对秒。**双键并存**：`startSec`/`endSec`（契约名）＋ `startSeconds`/`endSeconds`（旧名） |
| 时长/预算 | 毫秒，命名 `*Ms`（`effectiveMs`、`budgetMs`、`activeMs`） |
| 材料身份 | `materialId` + `materialVersion`，**不得用文件路径** |
| ID 生成 | `attemptId` / `markId` / `practiceId` / `reviewId` 由**服务端生成** |
| 幂等键 | 客户端传 `actionId` / `eventId` / `requestId`，服务端据此去重 |
| 错误格式 | `{"detail": {"code": "...", "message": "...", ...上下文}}` |
| 开发样例 | 带 `developmentFixture: true` |

**双键为什么并存**：前端已在用旧键，一次切换风险大。双键是过渡方案，
新代码用契约名，旧键保留到前端全部迁移后再删（不在本轮）。

## 2. 事件（七种，不是三种）

`POST /api/cet/practices/{practiceId}/events`

### 2.1 完整集合

| 类型 | 类别 | 用途 |
| --- | --- | --- |
| `playback_start` | 播放 | 开始播放 |
| `playback_end` | 播放 | 结束，携带计时 |
| `playback_interrupt` | 播放 | 被打断 |
| `visibility` | 业务 | 前后台切换（**前端依赖**，后台计时靠它） |
| `activity_heartbeat` | 业务 | 前台心跳 |
| `feedback` | 业务 | 反馈落库 |
| `transfer_answer` | 业务 | 换句作答（**前端依赖**） |

**短名别名**（Mock 与真实后端都必须接受，新代码发全名）：

```
start     → playback_start
end       → playback_end
interrupt → playback_interrupt
```

**其他类型一律 422**（如 `pause`）。注意：拒绝的是**未定义类型**，
不是短名——短名是合法别名。

### 2.2 各类型的必填参数

| 类型 | 必填 | 说明 |
| --- | --- | --- |
| `playback_start` | `audioTime`、`speed` | `speed` 必须等于当前步骤 `speed`（容差 0.001） |
| `playback_end` / `playback_interrupt` | `audioTime`、`speed`、`activeMs` | 必须有**未消费的** `playback_start` |
| `activity_heartbeat` | `activeMs` ∈ [1, 5000] | 单次上限 5000ms |
| `visibility` | `visible`（布尔） | 判定前台/后台 |
| `feedback` | `feedback` ∈ `sound`/`meaning`/`heard` | 需当前步骤已完整播放 |
| `transfer_answer` | `answer` | 当前步骤必须是换句检查 |

### 2.3 计时口径（实测，容易踩坑）

**前台/后台判定看最近一次 `visibility` 事件，不看请求体的 `visible` 字段。**
测试里若只传 `visible: false` 而不发 `visibility` 事件，后台播放仍会计时。

**「是否播完」与「计时多少」是两件事**，分开表达：

| 字段 | 含义 |
| --- | --- |
| `event.playedToEnd` | 这次是否完整播到步骤终点（`audioTime` 接近 `endSec`） |
| `event.appliedMs` | 这次实际计入的有效时长 |

前台实际播放多少就计多少，**没有 80% 比例门槛**。
「播完门槛」用于判断这次算不算完整听了一遍（`playedToEnd`），
不用于截断时长。

### 2.4 请求与响应

```json
{
  "eventId": "ev-xxx",
  "type": "playback_end",
  "stepId": "<当前步骤>",
  "materialVersion": "<材料版本>",
  "audioTime": 38.5,
  "speed": 1.0,
  "activeMs": 4000
}
```

响应顶层带 `effectiveMs` 与 `status`，并有 `event` 子对象：

```json
{
  "event": {
    "eventId": "ev-xxx",
    "duplicate": false,
    "appliedMs": 4000,
    "playedToEnd": true,
    "startEventId": "ev-yyy"
  }
}
```

## 4. 两套状态枚举（不得混用）

冻结约定 §2 的核心要求：**`succeeded` 与 `complete` 属于不同对象**，
不是同一枚举的两种写法。

| 场景 | 枚举 |
| --- | --- |
| 练习状态 | `active` / `complete` |
| **AI 请求状态** | `idle` / `pending` / `succeeded` / `failed` / `cancelled` / `stale` |
| 复习会话 | `ready` / `active` / `paused` / `complete` |
| 复习条目 | `current` / `pending` / `done` / `skipped` |
| 反馈 | `sound` / `meaning` / `heard` |

**常见错误**：用 `complete` 表示「模型调用成功了」。
那会让前端无法区分「这次 AI 成功了」和「这个练习做完了」。
模型成功一律 `succeeded`。

## 5. 交卷（Attempt）

`POST /api/cet/attempts`

```json
{
  "materialId": "cet6-202512-conv2",
  "materialVersion": "sha256-...",
  "listeningSessionId": "session-abc",
  "answers": [{ "questionId": "cet-q05", "choice": 1 }]
}
```

- `choice` 是 **0-based 选项索引**
- **幂等**：同一 `materialId` + 非空 `listeningSessionId` 只能有一条记录
- **交卷后不能改答案**：
  - 重复提交**完全相同**的答案 → 幂等返回原记录
  - 重复提交**不同**答案 → **409 `ATTEMPT_ANSWER_CONFLICT`**，响应含 `changedQuestionIds`
- 空 session 不参与唯一约束（旧客户端只传 `attemptId` 时保留多份）

响应 `results[]` 每条含 `questionId` / `number` / `choice` / `answer` / `correct` /
`answerSource` / `evidenceRef` / `explanation`

- **未作答**：`choice: null`、`correct: null`（**不是** `false`），计入 `unansweredCount`
- **未知答案**：`answer: null`、`correct: null`，计入 `unknownCount`

`GET /api/cet/attempts/{attemptId}` 可取回同一结构（刷新恢复用）。

## 6. 复习（Review）

`POST /api/cet/reviews` 请求 `{ "maxItems": 3, "budgetMs": 600000 }`

| 契约名 | 旧名 | 说明 |
| --- | --- | --- |
| `reviewId` | `id` | 会话 ID |
| `items` | `entries` | 条目列表 |
| `count` | — | 条目数 |
| `budgetMs` / `effectiveMs` / `remainingMs` | — | 预算与用时（毫秒） |

条目字段：`entryId`/`id`、`itemId`、`order`/`position`、`status`、`practiceId`、`item`

- **`order` 是 1-based**（第 1 处、第 2 处…）；`position` 保留 0-based 内部索引
- **条目状态**：`current` / `pending` / `done` / `skipped`
- **会话状态**：`ready` / `active` / `paused` / `complete`

`POST /api/cet/reviews/{reviewId}/actions`

```json
{ "action": "complete", "actionId": "rv-xxx", "itemId": "item-001" }
```

- **`actionId` 必填**（幂等去重）
- 动作：`start` / `pause` / `resume` / `skip` / `complete` / `replace` / `finish`
- `skip` **不记为完成**（跳过 ≠ 听懂）：状态落 `skipped`，条目仍在会话里
- **`replace`** 把当前条目换成尚未纳入的卡点，**条目数不变**，
  被换下的那一处记录在 `replacedFrom`；没有可换的卡点必须报错，不能静默成功

### 6.1 复习计时怎么走

真实后端**没有** `tick` 动作。复习处于 `active` 时，对**当前条目的练习**
发 `activity_heartbeat`（或播放类事件），后端据此累计 `effectiveMs`：

- 只有复习 `active` **且**前台（最近一次 `visibility` 为 true）才累计
- 累计会被**截断到剩余预算**，不会超
- 预算耗尽后会话转 `complete`，复习层 `effectiveMs` 不再增长

`tick` / `done` 是早期 Mock 自造的动作，**仅作 Mock 兼容保留，不是契约**。

## 7. 标记（Mark）

`POST /api/cet/marks`

```json
{
  "materialId": "cet6-202512-conv2",
  "materialVersion": "sha256-...",
  "listeningSessionId": "session-abc",
  "pressedAtSec": 36.9,
  "reactionDelaySeconds": 0.6
}
```

- `pressedAtSec` 是**按下空格时的媒体时间**（不是系统时钟）
- **吸附点 = `pressedAtSec - reactionDelaySeconds × speed`**，默认延迟 0.6s
- `markId` 由服务端生成；响应含 `suggestedSentenceId`（吸附建议）

> **测试注意**：断言「按键落在句中就该吸到该句」时必须显式传
> `reactionDelaySeconds: 0`。默认 0.6s 在短句上会跨过前一句终点，
> 于是「用句中点测吸附」会误判成后端吸错（实测 32 句中 5 句如此，
> 传 0 后 32/32 全部吸对）。

`PATCH /api/cet/marks/{markId}` 请求 `{ "confirmedSentenceId": "v2-2181-11" }`

**前置条件**：必须先交卷（否则 `409 ATTEMPT_REQUIRED`）。

## 9. AI 请求状态与取消

`GET /api/cet/practices/{practiceId}/ai-status`

```json
{
  "practiceId": "practice-xxx",
  "status": "pending",
  "aiRequest": { "requestId": "req-xxx", "status": "pending", "action": "explain", "createdAt": "..." }
}
```

状态：`idle` / `pending` / `succeeded` / `failed` / `cancelled` / `stale`

`POST /api/cet/practices/{practiceId}/ai-cancel` 请求 `{ "requestId": "req-xxx" }`

- **`requestId` 参与判断**：只取消匹配当前 active 的请求，不误伤新请求
- 不传时只取消当前 active 请求
- 取消后**保留请求记录与终态**，`aiRequest` 不为 null
- **迟到响应不能把 `cancelled` 覆盖成 `stale`**
- 语义区分：被新动作取代 → `stale`；用户主动取消 → `cancelled`
- **失败/取消后终态仍可查**（`ai-status` 返回 `failed` 与 `errorCode`，
  不能退回 `idle`）

`POST /api/cet/practices/{practiceId}/next` 请求
`{ "feedback": "meaning", "stepId": "...", "materialVersion": "..." }`

- **`stepId` 与 `materialVersion` 必填**
- `sound` → `slow`（本地，不调模型）
- `meaning` → `explain`（**调模型**）
- `heard` → `transfer`（**调模型**）

## 10. 材料

`GET /api/cet/materials` → `{ "items": [...], "count": N }`

`GET /api/cet/materials/{materialId}?version=...`

```json
{
  "material": {
    "materialId": "cet6-202512-conv2",
    "materialVersion": "sha256-...",
    "title": "...",
    "level": "cet6",
    "audioUrl": "/output/v2_assets/2181/cet6-202512-conv2.mp3",
    "durationSec": 105.486,
    "sentenceCount": 32,
    "questionCount": 5
  },
  "sentences": [
    {
      "sentenceId": "v2-2181-0",
      "index": 0,
      "startSec": 0.01, "endSec": 3.49,
      "startSeconds": 0.01, "endSeconds": 3.49,
      "text": "...",
      "materialId": "...",
      "materialVersion": "..."
    }
  ]
}
```

- **`version` 不符必须 409 拒绝**（不能返回 200）
- 句子身份用 `sentenceId`。真实服务形如 `v2-2181-0`，
  Mock 样例形如 `s01` —— **测试不得假设某一种形式**，
  必须用目标服务自己返回的 `sentenceId` 比对

**交卷前硬约束**：不返回 `answer` / `correct` / `evidenceRef` / `explanation` / `answerSource`。

## 11. 错误码

| 码 | HTTP | 含义 |
| --- | --- | --- |
| `MATERIAL_NOT_FOUND` | 404 | 材料不存在 |
| `MATERIAL_VERSION_CHANGED` | 409 | 版本不符 |
| `ATTEMPT_REQUIRED` | 409 | 未交卷 |
| `ATTEMPT_ANSWER_CONFLICT` | 409 | 重复交卷但答案不同 |
| `STALE_RESPONSE` | 409 | 步骤/版本过期 |
| `PRACTICE_COMPLETE` | 409 | 练习已结束 |
| `PLAYBACK_REQUIRED` | 409 | `feedback`/`transfer_answer` 前未完整播放 |
| `PLAYBACK_START_REQUIRED` | 422 | `playback_end` 前没有未消费的 `playback_start` |
| `PLAYBACK_SPEED_MISMATCH` | 422 | 事件 `speed` 与步骤不符 |
| `PLAYBACK_OUT_OF_RANGE` | 422 | `audioTime` 超出步骤范围 |
| `INVALID_ACTIVE_TIME` | 422 | `activeMs` 非法（心跳要求 1–5000） |
| `INVALID_EVENT` | 422 | 事件类型不在七种之内 |
| `INVALID_LOCAL_ACTION` | 422 | 本地动作非法或缺 actionId |
| `INVALID_REVIEW_ACTION` | 422 | 复习动作非法或缺 actionId |
| `TRANSFER_NOT_ACTIVE` | 409 | 当前步骤不是换句检查 |
| `AI_NOT_CONFIGURED` | 503 | 模型未配置（**环境问题，非缺陷**） |
| `AI_INVALID_OUTPUT` | 502 | 模型输出未通过校验（**应拒绝且不写入步骤**） |
| `AI_TIMEOUT` | 504 | 模型超时 |

## 12. 受控模型验证（D02 重做说明）

`scripts/cet/run_contract_controlled.py` 在 `cet_ai._call` 边界注入模型响应，
保留真实路由、真实数据库、真实状态机，用来区分「协议差异」与「缺 key」。

**本版 fixture 的四条硬要求**（上一版全部违反）：

1. `keyPhrases` 从**输入原句**派生（连续子串），单句不足 2 词返回空数组
2. `chunk` 每段 ≤8 词、2–4 段、按序完整覆盖原句、不改写
3. **主动断言确实成功**：`explanation` 非空 + `keyPhrases` 合法 +
   `aiRequest.status == "succeeded"`，并**单独输出证据**，不只看总通过数
4. 分别注入 **成功 / 慢响应 / 格式错误 / 超时**，各自断言路径确实发生

**隔离要求**：脚本使用独立数据库（临时目录内复制隔离库）与空闲端口，
显式设置 `ELT_USER_DB`，并在设置后自检「隔离库 ≠ 日常库」。
上一版未设 `ELT_USER_DB`，`create_app()` 的 lifespan 会走
`db.DB_PATH`（日常库 `resources/vocab.db`），实测推进了 `v2_tags` 自增序列。

**已知边界**：原文 `"What?"` 只有 1 个词，在「2–4 段、每段 ≤8 词」
约束下无法合法分段。fixture 返回 `None` 并让调用方抛
`AI_INVALID_OUTPUT`，**不伪造非法响应**。

| 项 | 现状 |
| --- | --- |
| 旧字段仍在返回 | `startSeconds`/`endSeconds`、`showText`、`playRange`、`entries`、`id`（向后兼容），新代码应用契约名 |

| Mock 的 `aiMode` 故障注入 | Mock 专用；真实服务不实现，测试按目标身份跳过 |
