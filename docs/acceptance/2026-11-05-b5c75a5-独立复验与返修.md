## P1 · B01 · “任何成功回包都合并”会让旧状态覆盖新状态

本次 N2 的修复解决了冲突后不拉取状态的问题，却把旧成功回包重新无条件写回。

**真实浏览器复现，受控传输延迟：**

1. 当前练习点“没听清”；服务已经成功推进到 slow，仅将此成功响应延后 20 秒。
2. 在这期间点“不懂意思”，因旧 stepId 返回 409。新 resyncPractice 生效，页面恢复到 slow。
3. 再点“不懂意思”，使用同步后的正确步骤，服务返回新解释，页面显示正文。
4. 最早的 slow 响应晚到，JS:609 不比较 revision，直接覆盖 S.practice；JS:613 再因旧 seq 提前返回，所以页面正文仍是新解释，内存状态却变回旧步骤。
5. 点击“保存本轮”，发送了旧 stepId，返回 409，页面显示“保存失败：步骤或材料版本已变化，请刷新后重试”。

证据：[请求状态与 stepId 日志](./evidence/b5c75a5-independent/transport.jsonl)、[失败页面](./evidence/b5c75a5-independent/late-response-save.txt)、[截图](./evidence/b5c75a5-independent/late-response-save.png)、[harness](./evidence/b5c75a5-independent/server.py)。刷新重新读取服务状态后，正常保存通过；因此可定位为前端旧快照覆盖，而非保存接口本身失败。

根因位置：`frontend/static/cet-listening.js:602–615`。**一个成功响应只代表它生成时的服务状态，并不保证在到达浏览器时仍然最新。** 文案按序号过滤，不能保护先前已被覆盖的状态。

同时，`resyncPractice():554–563` 在 GET 返回后没有复核发起时的 practiceId 或 revision；切换练习时也存在旧查询覆盖新状态的代码风险，本轮未单独复现该跨练习分支。

**返修标准：**

- 统一处理反馈、resync、换句提交和保存的快照合并；核对练习身份、材料版本及 revision，状态不能被更小 revision 的结果回退。
- 冲突后仍可 GET 权威状态，但 GET 回包也要做身份与版本检查；不要再次退回“全部丢弃”或“全部接收”两个极端。
- 保留本轮“冲突后能继续”的正向场景，并增加“已继续到新步骤后，旧成功响应才到”的 UI 回归，最终必须能直接保存成功。
- 再覆盖保存完成后旧回包到达、切换练习后旧 resync 到达，确保完成态和当前练习不被覆盖。

## P1 · B02 · 新迁移会无条件删除历史作答及其答案

`backend/webapp/services/cet_service.py:446–467` 在 schema 初始化时执行：按 `(material_id, listening_session_id)` 分组，保留最小 rowid，删除其余所有 attempt，然后创建唯一索引。没有比较材料版本、答案或会话 ID 是否为空。

**构造旧库实测：**两条历史记录同材料，版本分别 v1/v2，答案分别 A/B。分别用空 session 和相同非空 session 测试；两种情况均从 2 条 attempt、2 条答案变为 1 条 attempt、1 条答案。v2/B 被删除，唯一索引创建成功。答案表的 `ON DELETE CASCADE` 使答案一起消失。

证据：[迁移前后结果](./evidence/b5c75a5-independent/concurrency-migration.json)、[复现脚本](./evidence/b5c75a5-independent/concurrency-migration.py)。这个构造场景证明删除范围过宽，不代表原库发生了同样损失。

原接口兼容客户端提供 attemptId 而不提供 sessionId，所以空 session 不能被视为“同一次听音”。即使是非空 session，历史实现曾允许产生多条记录，也不能不核对内容就将所有记录视为可丢弃副本。旧客户端保存的 attemptId 还可能因此失效。

**返修标准：**

- 移除启动时无条件 DELETE；先盘点冲突并保留原始 attempt、答案和旧 ID 的可追溯关系。需要合并时采用可回滚迁移或归档映射，不直接丢历史。
- 明确空 session、材料版本变化和真实完全重复各自的处理方式；新记录的并发唯一约束应保留。
- 迁移失败不能 `except Exception: pass` 静默恢复成已知有竞争问题的实现。明确报告迁移/索引状态，失败回滚。
- 测试旧库升级、不同版本/答案、空 session、重复运行、失败回滚，并核对历史记录仍能查询。只测新库并发 6 次返回同 ID 不足以验收迁移。
