## N1 · P1 · 两个基于同一步骤的并发反馈均被接受

**证据类型：受控并发调度，真实业务函数、真实数据库事务。**

在两次初始校验后、写反馈前用 barrier 同步两个线程；它们提交不同 requestId，但使用同一个 stepId，均为 sound。没有修改校验、写入或返回结果，只控制两个请求的交错时间。

结果：两个请求均 200；revision 从 5 到 7，步骤数从 4 到 6，反馈历史从 3 到 5。第二个请求仍携带最初旧步骤，却被应用到第一个请求推进后的步骤。

根因：`backend/db.py:72` 的默认 SQLite 连接未在首次 SELECT 前取得写事务；`cet_service.py:1359–1373` 的首次验证与之后写入之间仍可竞争。第二个请求等写锁后，重新 SELECT 得到最新 practice；1379 起调用 `_local_practice_action_conn(..., already_validated=True)`，跳过原请求 stepId 对新状态的再次检查。

这与上轮“409 后留下反馈”不同：**本次异常回滚已经有效，剩下的是过期请求被错误接受。**

返修标准：在受保护的事务/条件更新内比较请求的步骤及 revision，取得锁后的状态才可作为最终合法性依据；两个同旧步骤的不同请求最多一个推进，另一个明确冲突且不增加反馈历史。不要仅用顺序发送旧 stepId 的测试代替并发测试。

可重跑证据：[事务检查脚本](./evidence/944b1c0-independent/transaction-checks.py)。脚本先复制独立 transaction.db，再执行异常回滚和并发检查；先运行 probe 建立其前置记录。

## N2 · P2 · 过滤旧响应后没有同步权威状态，连续反馈会卡在旧步骤

**证据类型：真实浏览器与路由，在服务外围受控延迟响应。**

复现：

1. 对一处当前练习点“没听清”。服务正常完成步骤推进，只将这个成功 HTTP 响应延后 8 秒发送。
2. 成功响应未到时再点“不懂意思”；页面仍持有旧 stepId，服务返回 409。
3. 第一条成功响应到达时，由于 feedbackSeq 已被第二次点击增加，被前端丢弃。
4. 等待结束再点“不懂意思”，仍用同一旧 stepId，再次 409。页面只能提示“这一步已过期，请刷新后重试”。

[传输日志](./evidence/944b1c0-independent/transport.jsonl) 为同一旧 stepId 的 `sound 200 → meaning 409 → meaning 409`；[页面](./evidence/944b1c0-independent/race-after.txt)、[截图](./evidence/944b1c0-independent/race-after.png)。harness 只延迟成功回包，不伪造状态与接口结果。

根因：`frontend/static/cet-listening.js:541–629` 只允许最后发出的请求落地；最新请求失败后没有重新 GET 当前练习，因此同时丢掉了唯一能同步新步骤的成功回包。

返修标准：可选择单练习请求串行、排队最新反馈，或在冲突后拉取权威状态再让用户继续。保留即时回听等本地操作；避免提示用户不断刷新。成功/失败/换句提交/保存均采用一致的身份、步骤和状态合并规则。补“早请求成功但回包慢、晚请求冲突”的真实 UI 回归，不能只测旧响应不覆盖。

## N3 · P1 · 保存完成后前端仍保留 active 状态与操作入口

**证据类型：真实 UI、真实 API/数据库与源码。**

复现：当前练习点“保存本轮” → 显示“本轮已保存”，但卡点仍为“待练”，面板仍显示慢放步骤和三个反馈按钮 → 再点“不懂意思”收到“反馈失败：练习已结束”。

后端记录已经 complete，说明保存本身成功。问题在 `frontend/static/cet-listening.js:806–820`：finish 接口返回 `{practice, reviewItem}`，却直接 `S.practice = {...S.practice, ...r}`；status/currentStepId 没被更新为 r.practice 的真实状态，也未按完成状态重绘或停用反馈入口。

证据：[保存后的页面](./evidence/944b1c0-independent/save-result.txt)、[再次反馈失败](./evidence/944b1c0-independent/save-then-feedback.txt)、[数据库状态](./evidence/944b1c0-independent/save-db.json)。这是既有链路缺口，本轮补充定位，不声称由本次提交引入。

返修标准：归一化 finish 响应，合并 r.practice，正确显示“已保存/本轮已练”和后续复习入口；已完成练习不能继续发送 active 反馈。补保存后不刷新、刷新后、重开后三个场景。
