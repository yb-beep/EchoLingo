## ⚠️ 复现前必读：测试必须指向「本轮新起的服务」

`tests/test_cet_base_workspace.py` 会**真实写入学习进度**（这是 T10 要验的行为）。
如果你指向一个残留的旧服务实例（同端口、旧数据库），库里已有的旧进度会让
`test_t10_progress_does_not_leak_between_materials` 失败：

```
AssertionError: A 的进度未落在 55s 附近：0.212
```

**这是环境问题，不是代码问题。** 同一份代码指向新起的服务 → 25 passed。

正确做法（**每次都起新端口 + 新库**）：

```bash
# 1) 新库（不要复用旧库）
export QA_DIR=/tmp/cetbase-qa-$(date +%s)
mkdir -p "$QA_DIR/data" "$QA_DIR/config"

# 2) 确认端口没被占（换一个没被占的）
lsof -nP -iTCP:5186 -sTCP:LISTEN   # 应该没有输出

# 3) 起服务
cd /tmp/wt-base-player
ELT_USER_DB="$QA_DIR/data/vocab.db" ELT_CONFIG_DIR="$QA_DIR/config" ELT_PORT=5186 \
  .venv/bin/python backend/fastapi_server.py &

# 4) 导入材料
ELT_USER_DB="$QA_DIR/data/vocab.db" .venv/bin/python scripts/cet/import_materials.py --all

# 5) 测试明确指向这个端口
CET_BASE_URL=http://127.0.0.1:5186 ELT_CONFIG_DIR="$QA_DIR/config" \
  .venv/bin/python -m pytest tests/test_cet_base_workspace.py -q
```

另注：
- `ELT_USER_DB` **只用于起服务**，不要用它跑 pytest（会覆盖 `monkeypatch` 的
  `DB_PATH`，导致跨用例污染）。
- 跑全量回归时用空 `ELT_CONFIG_DIR`，否则仓库根 `.env` 会在 import 期
  `load_dotenv()` 注入 `ELT_USER_DB`。

## 1. 材料列表与详情

### 1.1 列表

```http
GET /api/cet/materials
```

返回（节选，实测 2026-11-05）：

```json
{
  "items": [
    {
      "materialId": "cet6-202512-conv2",
      "materialVersion": "sha256-eb5a8c8540651205a594c24a",
      "id": "cet6-202512-conv2",
      "version": "sha256-eb5a8c8540651205a594c24a",
      "title": "2025年12月六级第一套 · Conversation Two",
      "level": "cet6",
      "section": "",
      "audioUrl": "/output/v2_assets/cet/cet6-202512-conv2.mp3",
      "lessonUrl": "/workspace/1",
      "audioSha256": "de98e7de987d400cb05fe957f21b5a4fa57112df9676bdb4c3f6214ff8a34259",
      "durationSec": 105.486349,
      "durationSeconds": 105.486349,
      "source": {"type": "cetMaterial", "value": "file://cet6-202512-conv2.mp3", "materialStore": "echolingo.v2_lessons"},
      "sentenceCount": 32,
      "questionCount": 5,
      "developmentFixture": false
    }
  ],
  "count": 2
}
```

字段口径：
- `materialId` / `materialVersion` —— **业务身份**，由 `cet_service._business_id()` 与
  `mediaUrl + segments` 派生。派生不出时回退 `v2-<lesson_id>`。
- `lessonUrl` 里的数字就是底座 `v2_lessons.id`（页面路由 `/workspace/<id>`）。
- `developmentFixture` 为 `true` 时**不是真题**，界面上不能标成「真题」。

### 1.2 按底座 lesson id 反查（队友模块现在用的就是这条）

```http
GET /api/cet/materials/by-lesson/{lesson_id}
```

- 是四六级材料 → 200，返回上面的对象 + `sentences` 数组
- 不是四六级材料 → **404**（`detail.code = "NOT_CET_MATERIAL"`）

`cet-listening.js` 的 `boot()` 依赖这个 404 来决定「不挂载卡点控件」，
**这个语义不会变**。

### 1.3 句子索引

`sentences[]` 每项（实测）：

```json
{
  "materialId": "v2-1",
  "materialVersion": "sha256-eb5a8c8540651205a594c24a",
  "sentenceId": "v2-1-0",
  "index": 0,
  "startSec": 0.01,
  "endSec": 3.49,
  "startSeconds": 0.01,
  "endSeconds": 3.49,
  "text": "It's getting late and we're both displaying signs of weariness.",
  "timingSource": "echolingo.v2_subtitle_segments"
}
```

- `sentenceId` 形如 `v2-<lesson_id>-<0based_index>`，是**证据句 ID**，
  题目里的 `evidenceSentenceId` 用的就是它
- `startSec`/`endSec` 与 `startSeconds`/`endSeconds` 是同一值的两个别名（历史兼容），
  新代码建议用 `startSec`/`endSec`
- `timingSource` 说明时间轴来源；`mfa_available: false` 时**没有词级时间轴**，
  只承诺句级回放，不要伪装词级精度

### 1.4 级别与版本

| 概念 | 来源 | 说明 |
| --- | --- | --- |
| 级别 | `v2_lessons.tags`，认 `cet4`/`cet6`/`四级`/`六级` | 否则 `unspecified`（= 待分类） |
| 版本 | `materialVersion` = `sha256-<24hex>` | 由 `mediaUrl + segments` 计算 |

**不要**按标题关键词推断级别，**不要**把 `level=cet4` 直接叫「四级真题」。

### 1.5 题目与作答

```http
GET  /api/cet/materials/{materialId}/questions?version={materialVersion}
POST /api/cet/attempts
GET  /api/cet/attempts/{attemptId}
```

题目结构、判题、未知答案判 null 的行为**全部由队友模块与 `cet_service` 决定**，
本板块不介入、不改动。

## 3. 播放器获取方式

### 3.1 DOM

| 元素 | 说明 |
| --- | --- |
| `#local-media-player` | 本地音频/视频元素（**推荐**）。音频课是 `<audio>`，视频课是 `<video>` |
| `#youtube-player` | 播放器容器（`#local-media-player` 的父节点） |
| `#offscreen-playback-engine` | 隐藏的区间试听引擎，不要拿它当主播放器 |

`#local-media-player` 由 `workspace.html` 在 `status` 接口回来后才创建，
**可能晚于你的模块 boot**。你的 `waitForPlayerThenTimeline()` 已经处理了这点，
继续用没问题。

### 3.2 JS 全局（推荐，底座保证字段只增不改）

```js
window.__ws
```

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `lessonId` | number | 底座 lesson id |
| `cetOn` | bool | 是否 CET 模式 |
| `features` | object | `{feature_key: bool}`，来自 `cet_mode` |
| `lesson` | object\|null | 完整 lesson 记录（`media_url`/`title`/`duration`/`subtitle_status`…） |
| `title` | string | 当前材料标题 |
| `mediaUrl` | string | 当前音频地址 |
| `mediaKind` | string | `audio` / `video` / … |
| `duration` | number | 秒 |
| `mode` | string | `listening` / `reading` |
| `availableModes` | string[] | 可用学习模式 |
| `sentences` | object[] | `{index, start, end, text, segment_ids, highlighted_words, word_meanings}` |
| `segments` | object[] | 原始字幕段（含 `highlighted_words`） |
| `activeSentenceIndex` | number | 当前句索引，`-1` 表示未定位 |
| `activeSentence` | object\|null | 当前句对象 |
| `currentTime` | number\|null | 播放器真实时间 |
| `audio` | HTMLElement\|null | 即 `#local-media-player` |
| `player` | object\|null | `localMedia` 或 `ytPlayer` |

**关键点：`sentences` 是「句」，不是「字幕段」。** 一个句可能由多个 segment 合并
（`segment_ids` 里是段索引）。收藏句用的是 `segment_ids[0]`。

### 3.3 控制方法

```js
window.__ws.seek(seconds)      // 跳转（元数据未就绪时会挂起，就绪后自动落地）
window.__ws.play()             // 播放
window.__ws.pause()            // 暂停
window.__ws.setRate(1.5)       // 设置倍速，返回生效值
window.__ws.getRate()          // 当前倍速
window.__ws.jumpSentence(-1)   // 逐句切换（会 clamp 到首尾）
window.__ws.refreshLesson()    // 重新拉取 lesson/字幕/收藏状态
```

这些都转发到页面原有实现（`seekTo` / `playMediaPlayback` / `onPlaybackRateChange` /
`jumpSentence`），**没有第二套播放状态**。你调用它们不会和原页面打架。

底座自己的模块也只用这些：

```js
window.__cetPlayer      // { isMounted, mount, updateBar, restorePosition, saveProgress,
                        //   fetchProgress, currentSegmentIndex, hasPlayer, audioEl,
                        //   cetListeningEnabled, ownsSpaceKey: false, _state }
window.__cetFavorites   // { isMounted, mount, reload, jumpToSentence, sentenceForWord,
                        //   removeWord, removeSentence, getState }
```

## 5. 快捷键归属

### 5.1 结论

**空格键归队友模块。** 底座播放器**不注册任何全局 keydown**。

```js
window.__cetPlayer.ownsSpaceKey === false   // 明确声明
```

### 5.2 底座这边做了什么

- `cet-player.js` 里没有 `keydown`/`keyup` 监听，没有 `'Space'` 字符串
  （`tests/test_cet_base_player.py::test_base_player_does_not_own_space_key` 守着）
- 底座只提供一个**查询接口**给你判断，不替你决定：

```js
window.__cetPlayer.cetListeningEnabled()
// → true 当 body.cet-listening 或 #cet-toolbar 已挂载
```

- 底座将来若要加快捷键，只允许用**不带 Space 的组合键**，并且必须先检查
  `cetListeningEnabled()`

### 5.3 队友模块现状（供对照，未改动）

`cet-listening.js` 的 `onKeyDown`：
- `e.code !== 'Space'` 直接 return
- `!S.listening` 直接 return（**未进入练习模式时完全不抢空格**）
- 输入框/textarea/select/contenteditable/弹窗不抢
- 聚焦在非 cet 按钮上不抢（按钮的空格是「点击」）
- `e.repeat` 忽略长按
- 暂停时空格恢复播放；播放中才创建标记

这套行为本板块**没有改动**，验收时按原样测。

## 6. 关键事件

### 6.1 底座发出的

| 事件 | 时机 | 监听方 |
| --- | --- | --- |
| `cet:sentence-change` | 当前句变化 | `cet-player.js` 刷新状态条 |
| `cet:favorites-changed` | 收藏变更 | `cet-favorites.js` 重新拉列表 |

两者都挂在 `document` 上，`CustomEvent`，无 `detail` 依赖。

### 6.2 底座提供的进度接口

```http
POST /api/v2/lessons/{lesson_id}/progress
body: {"last_position_seconds": 56.389, "last_segment_index": 17}

GET  /api/v2/lessons/{lesson_id}/progress
→ {"lesson_id": 1, "last_position_seconds": 56.389, "last_segment_index": 17, "updated_at": "..."}
```

- 写入节流 5 秒一次；`pause` / `seeked` / `pagehide` / `visibilitychange` 立即补写
- **用户主动 seek/play 后，异步回来的旧进度不会覆盖用户位置**（`markUserInteracted()`）
- 返回的 `lesson_id` 与当前 lesson 不一致时，底座**丢弃**该进度（防跨材料串数据）

### 6.3 收藏接口（底座使用，你可只读）

```http
GET    /api/v2/lessons/{id}/words
POST   /api/v2/lessons/{id}/word
DELETE /api/v2/lessons/{id}/word/{word}

GET    /api/v2/lessons/{id}/phase-b
POST   /api/v2/lessons/{id}/phase-b
DELETE /api/v2/lessons/{id}/phase-b/{segment_index}
```

- 句子收藏的 `segment_index` 就是**字幕段索引**，不是句索引
- 移除收藏**只删收藏记录，不删材料、不删句子、不删课程**

## 9. 已知限制（底座这边）

| 项 | 说明 |
| --- | --- |
| 词级时间轴 | `mfa_available: false`，只承诺句级。不要伪装词级精度 |
| 仅音频材料 | `subtitle_status='unavailable'` 是**独立终态**，不轮询、不弹错。此时没有句索引，你的卡点吸附会拿不到候选句 |
| 无 AI key | 「不懂意思」等 AI 动作降级为提示，回听/慢放/保存仍可用 |
