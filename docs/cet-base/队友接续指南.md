## 2. 你的模块现在是「关闭」状态 —— 这是有意为之

### 2.1 为什么默认关闭

独立验收方实测发现（BASE-05）：底座此前**无条件加载** `cet-listening.js/.css`，
导致**新导入的无题材料**也出现「开始卡点练习 / 今日复习 / 未交卷 / 交卷」等
**点了没反应的假入口**（点「交卷」`requests=[]`、状态不变）。

所以改成：**默认不加载，接入时开启**。

### 2.2 怎么开启（两种方式，任选）

**方式 A：环境变量（推荐用于验证，不改代码）**

```bash
ELT_CET_FEATURE_CET_LISTENING_AGENT=1 \
ELT_USER_DB="$CET_QA/data/vocab.db" ELT_CONFIG_DIR="$CET_QA/config" ELT_PORT=5300 \
  .venv/bin/python backend/fastapi_server.py &
```

**方式 B：改配置常量（推荐用于正式接入）**

```python
# backend/webapp/cet_mode.py 第 136 行附近
"cet_listening_agent": {
    "kept": True,        # ← 从 False 改为 True
    "label": "卡点陪练模块（队友交付）",
    "note": "队友卡点/智能复习模块；底座独立运行默认不挂载，真正接入后开启",
},
```

**模板一行都不用改。** `workspace.html:1859` 已经是：

```jinja
{% if cet_features.cet_listening_agent %}
<link rel="stylesheet" href="/static/cet-listening.css?v=20261105-c8">
<script src="/static/cet-listening.js?v=20261105-c8"></script>
...
{% endif %}
```

### 2.3 验证开关生效（不要用 route.abort()）

```bash

curl -s http://127.0.0.1:5300/workspace/1 | grep -c "cet-listening.js"    # → 0

# 开启态：资产在 DOM
```

> **验收方明确指出**：用 Playwright `route.abort()` 拦截资产**不算**关闭机制，
> 那只是测试技巧。请一律用上面的正式配置验证。

### 2.4 已知的第二层边界（你可能会想改）

`workspace.html:1863-1908` 有一段内联守卫，在**你的模块已挂载**时：

| 行为 | 判定 |
| --- | --- |
| 无题材料（`questionCount=0`）→ **移除** `#cet-questions` 面板 | 点交卷无反应，是假入口 |
| 「开始卡点练习」→ **保留** | 实测确实进入标记模式（`body.cet-listening=true`） |

**这段守卫只做幂等 DOM 移除，不碰你的算法。**
如果你在模块内部自己处理了无题材料，**可以安全删掉这段守卫**（它不会干扰有题材料）。

### 3.3 进度与收藏

### 3.4 空格键归属（返修2 P2-1 起为三态契约）

**不再是一句话「空格归你」。** 底座现在按队友模块开关状态动态决定是否接管：

| 状态 | 判定 | 底座是否注册快捷键 | `window.__cetPlayer.ownsSpaceKey` |
| --- | --- | --- | --- |
| CET 模式 + 队友模块**关闭** | `CET_ON && !cetListeningEnabled()` | **注册** Space/←/→/R/L | `true` |
| CET 模式 + 队友模块**开启** | `CET_ON && cetListeningEnabled()` | 不注册（让出） | `false` |
| 通用模式 | `ELT_CET_MODE=0` | 不注册（保持原样） | `false` |

**返修2 起底座在队友模块关闭时接管 Space/←/→/R/L，开启时让出。**

- 快捷键语义：`Space` 播放/暂停、`←`/`→` 上一句/下一句、`R` 重听当前句、
  `L` 当前句循环开关。
- 焦点在 `input`/`textarea`/`contenteditable` 时不响应。
- `ownsSpaceKey` 是**动态值**（反映当前是否实际接管），**不是常量**，不要缓存。

```python
# 验收方已确认的边界（返修2 起）
# 关闭态：底座注册 keydown，ownsSpaceKey=true，Space 真实翻转 paused
# 开启态：底座不注册，ownsSpaceKey=false，空格归队友模块
# 判定入口：window.__cetPlayer.cetListeningEnabled()
```

> **为什么改**：旧契约下队友模块默认关闭时，空格让给了一个不在场的模块，
> 工作区里没有任何播放快捷键（任务书 P2-1）。开启态行为与旧契约完全一致，
> 不存在双响应。

## 5. 三个必须知道的坑

### 坑 1：`ELT_USER_DB` 不能用来跑 pytest

```bash
# ❌ 错：会让所有测试写进同一个库、互相污染（表现为几十个无关用例集体失败）
ELT_USER_DB=/tmp/x.db .venv/bin/python -m pytest -q

# ✅ 对：跑测试只设 ELT_CONFIG_DIR
ELT_CONFIG_DIR=/tmp/x .venv/bin/python -m pytest -q
```

原因：`db.current_db_path()` 优先级是 `contextvar → ELT_USER_DB → DB_PATH`，
env 高于测试的 `monkeypatch.setattr(db, "DB_PATH", ...)`，静默覆盖隔离。

`ELT_USER_DB` **只用于起服务**做数据隔离。

### 坑 2：浏览器测试必须指向本轮新起的服务

```bash
# ❌ 错：指向残留的旧实例 → 库里已有旧进度 → T10 假失败
CET_BASE_URL=http://127.0.0.1:5186 pytest tests/test_cet_base_workspace.py

# ✅ 对：每次新端口 + 新库
CET_BASE_URL=http://127.0.0.1:5300 pytest tests/test_cet_base_workspace.py
```

不设 `CET_BASE_URL` 时整组会 **skip**（这是正确行为，不造假失败）。

### 坑 3：`.env` 会在 import 期注入环境变量

仓库根 `.env` 若有 `ELT_USER_DB=...`，`analyzer.py` / `ai_config.py` 在 import 期
`load_dotenv()` 会注入它。这就是坑 1 的根源。

`tests/conftest.py` 已有三道护栏（import 期摘 env、`DB_PATH` 指向正式库副本、
每用例前再摘一次），但你**自己写的临时脚本**要留意。
