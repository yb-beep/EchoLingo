## 逐页要点（C 负责的部分）

### P1 封面

- 标题：四六级听力黑匣子
- 副标题建议：**把「没跟上」的那一刻留下来，变成可以反复练的地方**
- 一行说明：基于 EchoLingo 开源底座改造

### P2 一句话说清做什么

> 四六级听力听不懂，通常不是整段都不懂，而是**某一句没跟上，后面就全乱了**。
>
> 我们的做法：听的时候，没跟上就按一下空格。交卷后回到那个位置，
> 确认真正卡住的句子，再按「没听清」还是「不懂意思」得到不同的帮助，
> 然后隐藏文字、原速回听，最后换一条真实原声验证。

**为什么这个叙事有力**：它把「听力差」这个模糊问题，落到一个可操作的动作上。

### P3 问题（【待填】需用户调研）

需要补充的真实性材料：
- 目标用户是谁（备考四六级的高校学生）
- 现状：怎么练听力、遇到什么困难
- 【待填】1—2 条真实用户说法或自己的体验

> C 建议：哪怕只有一句自己或同学的真心话，也比编数据强。评审看得出。

### P4 现有工具缺什么

关键对比（**要具体，不要说「不好用」**）：

| 现有工具 | 能做什么 | 缺什么 |
| --- | --- | --- |
| 普通播放器 | 重复播放、倍速 | 不知道你卡在哪句 |
| 精听软件 | 逐句切分、听写 | 记录卡点，但不驱动「下一步练什么」 |
| 背单词 App | 词汇记忆 | 不解决「听不出来」 |
| AI 对话 | 讲解、翻译 | 不保留你的卡点历程 |

**结论**：缺的是「卡点 → 带练 → 复习」这条链，而不是又一个播放器。

### P12 我们怎么验证它是对的（C 的强项，建议重点讲）

这一页能显著提升「技术性」评分，因为大多数参赛作品只演示、不验证。

可用的实测数据（全部有命令可复现）：

| 验证项 | 结果 |
| --- | --- |
| 契约测试 | **56 条**，覆盖契约全部可验部分 |
| 浏览器端到端 | 12 步全链路（跨端口 CORS 真实验证） |
| 句边界独立复核 | Whisper 独立转写交叉比对，**文字 32/32、边界 32/32** |
| 并发一致性 | 4 条并发用例（同一会话并发交卷只产生一个 attemptId） |
| 启动检查 | 21 项环境检查，新克隆四步补齐已实测 |
| 合规审计 | 密钥/许可/媒体/访问范围自动检查 |

**值得讲的一个故事**（真实性很强）：
> 我们用 Whisper 对同一段音频做独立转写，发现契约数据里有一句话被算了两次
> （s30/s31）。这是纯靠人工听很难发现的。修复后文字吻合从 29/32 提升到 32/32。

### P13 已知限制（诚实说，反而加分）

- 目前只验证了 1 段真实六级材料（Conversation Two，105 秒）
- 句子边界经机器交叉复核，但**最终人耳确认尚未完成**
- AI 带练在无密钥环境下走本地兜底动作
- 换句检查的候选结构仍待后端确认
- 上游许可为 PolyForm Noncommercial，商业化前需确认适用范围

> C 的建议：这一页不要删。评审见过太多「完美无缺」的项目，
> 主动说边界反而显得可信。

## 制作注意事项

1. **截图要真机截**，不要用设计稿模拟——评审能看出来。
2. **区分真实输出/缓存/模拟**：凡是用 Mock 数据做的截图，标注「开发样例」。
3. 字体统一，中文用系统字体，避免缺字。
4. 每页只讲一个点，不要塞满。
5. 视频与 PPT 的演示段落要能对上（同一个操作顺序）。
