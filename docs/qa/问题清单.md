### BUG-001 · FastAPI 0.162 让 `app.routes` 不再扁平，内省式自检全挂

| 字段 | 内容 |
| --- | --- |
| 严重度 | **P1**（不影响运行时，但传染所有路由自检代码） |
| 状态 | `已分配` → **B**（依赖锁策略需三人同意） |
| 版本 | 底座 `1ea5b35`；FastAPI **0.162.0**（`requirements.txt` 未锁版本） |
| 前置条件 | 新建 venv 并按 `requirements.txt` 安装（无版本锁，会拿到 0.16x） |

**操作步骤**

```bash
cd /Users/a1111/Documents/ChatGPT/EchoLingo-cet
.venv/bin/python -c "
import sys; sys.path.insert(0,'backend')
from fastapi_server import create_app
app = create_app()
print(len(app.routes), sum(1 for r in app.routes if hasattr(r,'path')))
"
```

**预期**：`app.routes` 里每个元素都有 `.path`，可枚举全部已注册路由。

**实际**：`17 5`
类型分布 `{'_IncludedRouter': 12, 'Route': 4, 'Mount': 1}`，**只有 5 个有 `.path`**。

**连带影响**：`tests/test_public_single_user_compat.py::test_fastapi_server_starts_single_user_without_private_modules` 失败（`AttributeError: '_IncludedRouter' object has no attribute 'path'`）。任何 `{r.path for r in app.routes}` 写法都会挂，B/C 写 CET 路由自检时必踩。

**证据**：`app.routes` 类型计数如上；同进程 `/api/openapi.json` 仍正常返回 **132 条路径**，所有 HTTP 端点实测可通 → 说明这是**内省方式**的问题，不是路由注册的问题。

**绕法（已验证可用）**：用 `app.openapi()["paths"]` 枚举，不要遍历 `app.routes`。

**待决**：是否在 `requirements.txt` 锁 `fastapi==0.115.*`。锁版本会改变 B 的开发环境，**C 不单方面改**，需三人同步后由 B 落到依赖文件。

**复验结果**：（待修）

### BUG-002 · 无 AI 密钥时所有 AI 接口返回 500，而非可展示的「未配置」错误

| 字段 | 内容 |
| --- | --- |
| 严重度 | **P1**（阻断带练与换句的真实链路验收） |
| 状态 | `已分配` → **B** |
| 版本 | 底座 `1ea5b35` |
| 前置条件 | `.env` 中 `AI_API_KEY` 为空（当前默认状态） |

**操作步骤**

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:5173/api/hint \
  -H 'Content-Type: application/json' -d '{"sentence":"test","level":1}'
```

**预期**：返回明确的「模型未配置」错误（如 4xx + 可展示的 `error_info`），页面上能提示用户去设置页填密钥。

**实际**：**HTTP 500**，错误体透出上游 `Error code: 401 - Authentication Fails, Your api key: ****-key is invalid`。
`/api/practice`、`/api/oral-analysis`、`/analyze-word` 同样 500。

**根因（C 定位）**：`backend/webapp/runtime/ai_config.py` 在 `AI_API_KEY` 为空时用占位符 `"missing-api-key"` 构造 OpenAI client。文件注释声称「AI endpoints report key missing before any request is attempted」，**但实际代码没有前置拦截**，直接发请求拿到 401 再被包成 500。

**证据**：`/health` 明确返回 `keys.AI_API_KEY = "missing"`；四个 AI 端点实测 500，错误文本一致。

**影响**：无密钥环境下任何依赖模型的用例都 500。C 的 D1—D2 带练验收只能走 **Mock** 或 `POST /api/cet/practices/{id}/local` 本地动作，真模型验收需另找配好密钥的机器并单独标注。

**附带提醒**：错误文本会回显脱敏后的密钥片段（`****-key is invalid`）。写测试断言时不要整串比对，也不要把响应原文贴进交付物。

**复验结果**：（待修）

### BUG-007 · `start_cet.sh` 中 `$VAR` 紧跟中文标点导致 `unbound variable`

| 字段 | 内容 |
| --- | --- |
| 严重度 | **P0**（启动脚本直接失败） |
| 状态 | ✅ **已复验**（C 修复） |
| 归属 | C |

**修复**：脚本内所有 `$VAR` 后紧跟非 ASCII 字符处改为 `${VAR}`。已用正则全量排查 `start_cet.sh` / `stop_cet.sh`，共修 15 处。

**复验**：`bash -n` 通过；从停止状态完整启动成功，退出码 0。
