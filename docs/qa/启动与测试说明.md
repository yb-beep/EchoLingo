## 3. 每次启动（已脚本化）

### 3.1 启动

```bash
scripts/qa/start_cet.sh              # 只启动底座
scripts/qa/start_cet.sh --mock       # 底座 + Mock API（前端要 Mock 时用）
scripts/qa/start_cet.sh --fg         # 前台运行，日志直接打屏（排查用）
PORT=5174 scripts/qa/start_cet.sh    # 换端口（同机第二个人用）
```

脚本做的事，按顺序：

1. 确认 `.venv/bin/python` 存在并打印版本；
2. 跑 `scripts/qa/check_env.py --skip-service`，**有阻断项直接退出**（不带坏环境启动）；
3. 检查端口：空闲则启动；若已有本项目底座在响应，**跳过底座只补 Mock**（不会因为底座在跑就整体失败）；
4. 创建并导出隔离数据目录；
5. `nohup` 后台启动，写 PID 文件；
6. **轮询 `/health` 等到真的能响应**才报成功（最多 40 秒，进程中途退出会打印日志尾部）；
7. `--mock` 时同样等 Mock 的 `_mock/info` 就绪才报成功。

### 3.2 停止

```bash
scripts/qa/stop_cet.sh           # 停底座与 Mock
scripts/qa/stop_cet.sh --mock    # 只停 Mock
scripts/qa/stop_cet.sh --all     # 连端口残留进程一起停（PID 文件丢了时用）
```

停止后会**逐一确认端口真的释放**，否则下次启动会撞端口。

### 3.3 已实际验证的启停闭环

| 步骤 | 命令 | 实际结果 |
| --- | --- | --- |
| 从停止状态启动 | `scripts/qa/start_cet.sh --mock` | 底座 PID 55307 就绪，Mock PID 55314 就绪，退出码 0 |
| 停止 | `scripts/qa/stop_cet.sh` | 两个进程均停止，端口 5173 / 5199 均释放 |
| 再次启动 | `scripts/qa/start_cet.sh --mock` | 正常；底座数据库 `quick_check=ok`，47 张表保留 |
| 底座在跑时补 Mock | `scripts/qa/start_cet.sh --mock --mock-only` | 正确跳过底座只起 Mock（此情形原先会误报端口冲突，已修） |

> 说明：**底座**数据在 `.cet-qa/data/vocab.db`，重启后保留，可验证恢复。
> **Mock API 是进程内存态**，重启即清空——这是设计如此（替身不该有持久化负担），
> 需要可复现状态请用 `POST /api/cet/_mock/reset` 重建，而不是指望它记住。

## 5. 密钥与模型配置（不写进任何交付物）

- 密钥只放 `.env` 或「设置」页，**不进源码、样例、日志、PPT、演示包**。
- 当前本机 `AI_API_KEY` **未配置**。实测：所有 AI 接口（`/api/hint`、`/api/practice`、`/api/oral-analysis`、`/analyze-word`）返回 **HTTP 500**，原因是上游 DeepSeek 报 401 被包成 500。
- 因此 D1—D2 的**带练链路验收**分两条路：
  1. **Mock**：`tests/mock_cet_api.py` 的 `next`/`local` 接口，验证契约与页面流转；
  2. **本地动作**：`POST /api/cet/practices/{id}/local`（replay/slow/chunk/explain），不依赖模型。
- 真模型验收必须在配好密钥的机器上单独跑，并在验收记录里**单独标注**为「真实模型输出」。
- 交接记录只写「已配置 / 未配置」，不写密钥内容。

## 7. 已知问题与限制（D1 实测）

### R1 · FastAPI 0.162 让 `app.routes` 不再扁平（P1，影响所有自检代码）

`requirements.txt` 里 `fastapi` **无版本锁**，新装环境会拿到 0.16x。实测：

```
app.routes 共 17 个元素 → {Route: 4, Mount: 1, _IncludedRouter: 12}
只有 5 个元素有 .path 属性
```

**运行时完全正常**（`/api/openapi.json` 仍返回 132 条路径，所有端点实测可通），但任何 `{route.path for route in app.routes}` 都会抛 `AttributeError`。

- 影响：`tests/test_public_single_user_compat.py` 失败；**B、C 写路由自检时必踩**。
- 规避：用 `app.openapi()["paths"]` 枚举路由，不要遍历 `app.routes`。
- 待定：是否锁 `fastapi==0.115.*`。锁版本会影响 B 的开发环境，需三人同意，**C 不单方面改**。

### R2 · 无密钥时 AI 接口返回 500 而非优雅降级（P1）

见 §5。`ai_config.py` 的注释声称会在请求前报「key missing」，实际直接用占位符 `"missing-api-key"` 发请求，拿到上游 401 后包成 500。

- 影响：无密钥环境下任何 AI 用例都 500，带练验收必须走 Mock 或本地动作。
- 归属：**B**（错误码与降级逻辑）。
- 注意：错误文本会透出 `****-key is invalid`（已脱敏）。测试断言不要整串比对。

### R3 · 底座数据全空（P2）

`/api/lessons`、`/api/v2/lessons/library`、`/api/active-words` 均为空结构。页面 200 且 DOM 完整，但**任何「列表非空」断言都会失败**。做有内容的 E2E 前需预置 fixture。

### R4 · `/api/docs` 依赖 CDN（P2）

Swagger UI 的 CSS/JS 指向 `cdn.jsdelivr.net`。离线/内网下页面 200 但白屏。若交付验收含「人工打开 API 文档」，需说明要联网。

### R5 · Whisper 模型只有 large-v3 就绪（P3）

`base`/`medium` 未缓存（`ready=false`）。CET 链路若选 base/medium 会触发下载或失败，**选 large-v3 才稳**。

### R6 · 路径前缀风格不一致（P3）

`/analyze-word`、`/analyze-connected-speech`、`/log-word` 无 `/api` 前缀，其余 AI 接口都有。B 新增 `/api/cet/*` 时保持统一，不要照抄这两个例外。

### R7 · `/api/cet/*` 命名空间干净（信息）

`POST /api/cet/marks`、`/api/cet/anything` 实测均 404，无既有实现、无路由冲突。**B 可安全新建。**

### R8 · 底座句子标记能力可参考但不能直接复用（信息）

`study.py` 提供 `GET/POST /api/sentence-mark(s)`，`db.py` 有 `set_sentence_mark` / `toggle_sentence_mark` / `get_sentence_marks`，表 `sentence_marks` 带 `UNIQUE(lesson_filename, sentence_idx)`，**已完整持久化**。

但键空间是 v1 的 `(filename, sentence_idx)`，与 CET 需要的 `(lesson_id, sentence_id)` 不兼容，且 v1 表与 v2 表族无外键关联。

- 建议 **B**：复用函数形状与幂等写法，键改挂 `lesson_id`/`sentence_id`；**不要直接写 `sentence_marks` 表**，否则 v1/v2 两套 ID 会混淆。

## 10. 卡住时先看这里

| 现象 | 先查 | 处理 |
| --- | --- | --- |
| `未找到虚拟环境解释器` | `.venv/bin/python` 是否存在 | 按 §2 建 venv（必须 3.11） |
| 启动即退出 | `.cet-qa/logs/server.log` 尾部 | 脚本已自动打印；多为依赖缺失或数据库锁 |
| 端口被占用 | `lsof -nP -iTCP:5173 -sTCP:LISTEN` | 换端口 `PORT=5174`，或 `stop_cet.sh --all` |
| 页面打得开但没声音 | 音频文件与 SHA-256 | 按 §8 核对；`check_env.py` 会直接报哈希不符 |
| AI 功能全 500 | `check_env.py` 的 AI 密钥项 | 无密钥属预期，走 Mock 或本地动作（§5） |
| 契约测试全失败 | `CET_API_BASE` 指向哪 | 真实服务未实现时失败是预期（§6.2） |
| 样例校验失败 | `build_fixtures.py --check` 输出 | 重新生成；手工改过的样例不算数 |
