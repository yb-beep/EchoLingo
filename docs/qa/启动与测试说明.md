### 2.1 新克隆仓库的四步补齐（已实测）

`.venv`、`.env`、样例音频都**不入库**，所以新克隆下来不能直接跑。
按这四步补齐 —— 这是 D3 换另一台电脑验收的实际流程，已在本机用全新克隆实测通过。

```bash
# 1) Python 3.11 虚拟环境（系统自带 python3 是 3.9，不能用）
python3.11 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt

# 2) 配置
cp .env.example .env

# 3) 把共同样例音频放到隔离目录（会核对 SHA-256）
.venv/bin/python scripts/qa/prepare_audio.py

# 4) 启动并自检
scripts/qa/start_cet.sh --mock
```

**第 3 步是关键**，也是新机器最容易卡住的地方。`prepare_audio.py` 会：

- 在几个候选位置找音频，逐个核对 SHA-256
- 找到就直接用，并打印 `--copy-from` 命令
- 哈希不符会明确拒绝（三人必须同一段，否则时间轴对不上）
- 找不到会给出三种获取途径

```bash
# 若音频在别处
.venv/bin/python scripts/qa/prepare_audio.py --copy-from /你的/路径/full.mp3
# 或用环境变量指向
export CET_QA_MEDIA=/你的/路径/full.mp3
```

**本机实测**（临时克隆到 `/tmp`）：
- 补齐前 `check_env.py` → **1 个阻断项**（缺音频），错误信息列了完整四步
- `prepare_audio.py` → 找到源文件但目标缺失，退出码 1 并给出确切复制命令
- 执行 `--copy-from` → 复制成功、哈希核对通过、退出码 0
- 补齐后 `check_env.py` → **无阻断项**

> 顺带修了一个会误导人的问题：`check_env.py` 原来只看 5173 端口有没有服务，
> 会**把另一个副本的服务当成自己的**报告（数据路径、数据库状态全是别人的）。
> 现在会核对服务归属，不属于本目录时明确警告并指出实际来源。

## 3. 每次启动（已脚本化）

### 3.1 启动

```bash
scripts/qa/start_cet.sh              # 只启动底座
scripts/qa/start_cet.sh --mock       # 底座 + Mock API（前端要 Mock 时用）
scripts/qa/start_cet.sh --fg         # 前台运行，日志直接打屏（排查用）
PORT=5174 scripts/qa/start_cet.sh    # 换端口（同机第二个人用）
```

脚本做的事，按顺序：

1. 确认 `.venv/bin/python` 存在并打印版本；
2. 跑 `scripts/qa/check_env.py --skip-service`，**有阻断项直接退出**（不带坏环境启动）；
3. 检查端口：空闲则启动；若已有本项目底座在响应，**跳过底座只补 Mock**（不会因为底座在跑就整体失败）；
4. 创建并导出隔离数据目录；
5. `nohup` 后台启动，写 PID 文件；
6. **轮询 `/health` 等到真的能响应**才报成功（最多 40 秒，进程中途退出会打印日志尾部）；
7. `--mock` 时同样等 Mock 的 `_mock/info` 就绪才报成功。

### 3.2 停止

```bash
scripts/qa/stop_cet.sh           # 停底座与 Mock
scripts/qa/stop_cet.sh --mock    # 只停 Mock
scripts/qa/stop_cet.sh --all     # 连端口残留进程一起停（PID 文件丢了时用）
```

停止后会**逐一确认端口真的释放**，否则下次启动会撞端口。

### 3.3 已实际验证的启停闭环

| 步骤 | 命令 | 实际结果 |
| --- | --- | --- |
| 从停止状态启动 | `scripts/qa/start_cet.sh --mock` | 底座 PID 55307 就绪，Mock PID 55314 就绪，退出码 0 |
| 停止 | `scripts/qa/stop_cet.sh` | 两个进程均停止，端口 5173 / 5199 均释放 |
| 再次启动 | `scripts/qa/start_cet.sh --mock` | 正常；底座数据库 `quick_check=ok`，47 张表保留 |
| 底座在跑时补 Mock | `scripts/qa/start_cet.sh --mock --mock-only` | 正确跳过底座只起 Mock（此情形原先会误报端口冲突，已修） |

> 说明：**底座**数据在 `.cet-qa/data/vocab.db`，重启后保留，可验证恢复。
> **Mock API 是进程内存态**，重启即清空——这是设计如此（替身不该有持久化负担），
> 需要可复现状态请用 `POST /api/cet/_mock/reset` 重建，而不是指望它记住。

### 6.3 契约样例自校验与 Mock 一致性

任务书有一句警告：「自己编写接口实现和断言时，两者一致本身不足以证明真实后端正确。」
同理，**Mock 悄悄偏离契约样例**也是一种真实风险 —— 那会让 Mock 测试全绿，
但 A 照着样例写前端反而对不上。

所以有两层保护：

**第一层：样例自身自校验**

```bash
.venv/bin/python tests/fixtures/cet/build_fixtures.py --check   # 只校验（CI 用）
.venv/bin/python tests/fixtures/cet/build_fixtures.py           # 重新生成
```

比对样例文件与生成脚本的输出是否一致（手工改过就会报错）。

生成器同时做**三层自校验**，任一不过就拒绝生成：
1. 句子时间轴（不倒置、不越界、不重叠、原文非空）
2. 题目（题号不重复、答案索引不越界、交卷前不含答案字段、unknown 来源必须 answer=null）
3. **状态枚举对照任务书 7.3**（feedback / 带练动作 / 练习状态 / 复习条目 / 复习会话）

第 3 层是补上来的：C 曾在 Mock 里自造 `skipped_pending`，因为断言写成子串匹配而漏过。
现在样例与生成器都不允许出现契约外的值。

**第二层：Mock 是否忠实实现样例**（仅 Mock 上跑）

`test_mock_matches_fixture_material_list` 与
`test_mock_questions_hide_same_fields_as_fixture` 断言：
- 契约定义的字段 Mock 不能少、不能改值（可多返回）
- **样例刻意不含的字段（`answer`/`evidenceRef`/`explanation`）Mock 也不能有** —— 否则就是泄题

已验证这两条真的能抓住偏差：把样例标题改坏后，
测试立刻报 `{'title': ('被故意改坏的标题', '2025年12月六级第一套 · Conversation Two')}`。

> 真实服务上这两条会跳过（真实后端本就不该与开发样例逐字相同）。

### 6.4 句边界机器交叉复核（Whisper 独立转写）

```bash
.venv/bin/python scripts/qa/verify_sentence_boundaries.py            # 默认 large-v3
.venv/bin/python scripts/qa/verify_sentence_boundaries.py --model small   # 更快
.venv/bin/python scripts/qa/verify_sentence_boundaries.py --refresh  # 重算转写
```

**为什么需要**：契约的 32 条句边界来自旧项目对齐产物，来源标注是「程序覆盖检查」，
**从没与音频内容做过独立比对**。时间轴校验只查数字（不倒置/不越界/不重叠），
**查不出「文字对不上」或「同一句算两遍」**。

这个脚本用 Whisper 做一次**独立转写**（词级时间戳），再交叉比对两件事：
1. 契约那句话范围内的语音，是不是真的在说这句话？（文字命中率）
2. 起止点是否落在该句首词/末词上？（边界偏差）

**它立刻抓到了一个真 bug（BUG-006d）**：s30 与 s31 把
"and the board too is virtually unanimous in its support" 算了两遍，
而音频里这句话只出现**一次**。修复前后对比：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 文字吻合 | 29/32 | **32/32** |
| 边界吻合 | 31/32 | **32/32** |

判定阈值（保守，宁可多报待复核）：
- 文字命中 ≥ 70%（数字/口语变体已归一化：`4`↔`four`、`OK`↔`Okay`）
- 起点偏差 ≤ 0.45s、终点偏差 ≤ 0.60s（句尾常有拖音）

> ⚠️ **不能替代人耳（H1）**。Whisper 也会听错、切错。
> 它的价值是把「明显切歪」筛出来，把需要人耳复核的范围从 32 条缩到 0 条。

### 6.5 底座数据预置（做有内容的 E2E 前先跑）

```bash
.venv/bin/python scripts/qa/seed_base_data.py           # 导入一节样例 reading 课
.venv/bin/python scripts/qa/seed_base_data.py --check   # 只查有没有数据
.venv/bin/python scripts/qa/seed_base_data.py --force   # 已有也再导一份
```

**为什么要这一步**：底座默认是干净的（47 张表但 0 行）。空库只能验「页面 200 + 骨架」，
验不了「页面把内容渲染出来了」。BUG-003 查清后确认导入链路本身正常，只是没人喂过数据。

**走真实导入接口，不直接写库**：直接插数据只能证明「我能写库」，证明不了「底座导入链路通」——
而后者才是要验的。

**本机实测**：导入完成 → 课程库 2 节 → 正文可读回（413 字符，内容匹配）→
句子标记可写可读（`[1]`）→ 工作台 `/workspace/2` 渲染出正文且无 JS 报错。

> 纯文本导入**没有句级时间轴**（`subtitle_status=pending`、`segments: []`），这是正常表现，不要误判为异常。
> 需要句级时间轴的场景必须走音视频导入，依赖 Whisper + FFmpeg。

### 6.6 浏览器层验证

```bash
.venv/bin/python scripts/qa/browser_check.py            # 全套（页面 + 音频 + Mock 文档）
.venv/bin/python scripts/qa/browser_check.py --headed   # 看见窗口，排查用
.venv/bin/python scripts/qa/browser_check.py --audio-only
```

**为什么需要这一层**：其余测试全走 HTTP，只能证明「接口返回了对的东西」，
不能证明「页面上真的能做」。这个脚本补两件事：

1. 底座页面能打开、标题正确、有关键入口、**无 JS 运行时错误**；
2. **样例音频被浏览器真的加载并解码**、时长与契约一致、可 seek、能定位到卡点句起点。

浏览器按可用性依次尝试：**playwright chromium → 本机 Chrome → 本机 Edge**。
D3 换电脑时，那台机器只要装了 Chrome 就能跑，不必先 `playwright install`。

**本机实测（2026-11-03，含预置数据）**：**15 项全部通过**
（使用本机 Chrome 156.0.8078.47 通道；`playwright install chromium` 下载慢，未等完）

> 其中「有内容时的页面渲染」3 项依赖 §6.4 先预置数据；未预置时会跳过并注明，不算失败。

> ⚠️ **这一层不能证明「声音内容与文字对得上」**。它只证明音频能解码、能定位到 36.77s。

### 6.8 后端接口缺口报告（给 B 用）

```bash
.venv/bin/python scripts/qa/check_backend_gap.py                    # 打真实服务
.venv/bin/python scripts/qa/check_backend_gap.py --json             # 机器可读
.venv/bin/python scripts/qa/check_backend_gap.py --base http://127.0.0.1:5199
```

**为什么需要**：真实服务上跑契约测试，B 只看到「41 failed」一堆红字，不知道从哪下手。
这份报告把失败**倒推成「哪些接口还没实现」**，按 5 个批次排好，B 照着做，
每完成一批就有一批用例转绿。

| 批次 | 内容 | 接口数 | 转绿用例 |
| --- | --- | --- | --- |
| 1 | 材料与句子 | 4 | 6 |
| 2 | 交卷与判题 | 1 | 5 |
| 3 | 标记与确认 | 3 | 8 |
| 4 | 练习与带练 | 6 | 13 |
| 5 | 卡点与复习 | 4 | 4 |

设计要点（踩过坑）：
- **不假定有 `/health`**：Mock 没有这个端点，用契约第一个接口探活。
- **区分「路由不存在」与「资源不存在」**：两者都是 404，但含义完全不同。
  FastAPI 路由没注册返回固定体 `{"detail":"Not Found"}`；
  路由在但资源不存在会带业务错误体（如 `code: MARK_NOT_FOUND`）。
  只看状态码会把 Mock 上已实现的接口误报成未实现 —— 这是个真实的误判，已修。
- **2xx 与业务 4xx 都算已实现**：参数错是正确的校验，不是缺失。

**当前结果**：真实服务 **18 个接口全部未实现**（退出码 1）；Mock **18/18 已实现**（退出码 0）。
两个目标都验过，说明判定逻辑本身可信。

### 6.9 集成分支合并与验证

```bash
.venv/bin/python scripts/qa/integrate.py --list                          # 看 A/B 有没有推分支
.venv/bin/python scripts/qa/integrate.py --merge codex/cet-frontend     # 合入并验证
.venv/bin/python scripts/qa/integrate.py --verify-only --fast           # 只验证当前状态
```

任务书要求「拿到提交就记录 SHA，合入一批，启动一次」。这个脚本把该流程固化：

| 行为 | 说明 |
| --- | --- |
| 合入 | 逐个 `--merge`，**每合一个立刻记录 SHA**；已在历史中的不重复合并但仍记 SHA |
| 验证 | 环境检查 → 契约测试（真实服务）→ 样例自校验 → 浏览器层 → 底座回归 |
| 报告 | 写 `.cet-qa/integration/latest.json`（含每个提交 SHA、合并结果、验证结果） |
| 冲突 | **报冲突文件、停止、保留现场**，不自动回退 |
| 安全 | 不 force push、不 `reset --hard`、不删分支；只动集成分支不动 `main` |

**退出码**：`0` 全绿｜`1` 合并或验证失败｜`2` 前置问题（工作区不干净等）

#### 已知基线失败的处理（重要）

BUG-001 是已登记的版本漂移。若每次集成都报红，久了就没人当真，门禁等于失效。
所以脚本按**用例名**豁免已登记项，并明确标注：

```
[OK] 底座回归
      [已知基线] tests/.../test_fastapi_server_starts_single_user_without_private_modules → BUG-001（不阻塞集成）
```

**只豁免已登记的那一个用例名。** 一旦出现别的失败项，仍判失败并标 `[新回归]`。
BUG-001 修复后应从 `KNOWN_BASELINE_FAILURES` 移除该豁免。

#### 已实测的三种路径

| 场景 | 结果 |
| --- | --- |
| 正常工作区 + 可合并分支 | 合并成功、验证全绿、报告生成、退出码 0 |
| 分支与集成分支改同一文件 | 报冲突文件 `conflict.txt`、停止、现场保留（`UU`）、报告含 `stoppedAt: merge`、退出码 1 |
| 工作区有未提交改动 | 拒绝执行并列出改动、退出码 2 |
| `--verify-only` | **不建不切分支**，只在当前分支验证 |

## 7. 已知问题与限制（D1 实测）

### R1 · FastAPI 0.162 让 `app.routes` 不再扁平（P1，影响所有自检代码）

`requirements.txt` 里 `fastapi` **无版本锁**，新装环境会拿到 0.16x。实测：

```
app.routes 共 17 个元素 → {Route: 4, Mount: 1, _IncludedRouter: 12}
只有 5 个元素有 .path 属性
```

**运行时完全正常**（`/api/openapi.json` 仍返回 132 条路径，所有端点实测可通），但任何 `{route.path for route in app.routes}` 都会抛 `AttributeError`。

- 影响：`tests/test_public_single_user_compat.py` 失败；**B、C 写路由自检时必踩**。
- 规避：用 `app.openapi()["paths"]` 枚举路由，不要遍历 `app.routes`。
- 待定：是否锁 `fastapi==0.115.*`。锁版本会影响 B 的开发环境，需三人同意，**C 不单方面改**。

### R2 · 无密钥时 AI 接口返回 500 而非优雅降级（P1）

见 §5。`ai_config.py` 的注释声称会在请求前报「key missing」，实际直接用占位符 `"missing-api-key"` 发请求，拿到上游 401 后包成 500。

- 影响：无密钥环境下任何 AI 用例都 500，带练验收必须走 Mock 或本地动作。
- 归属：**B**（错误码与降级逻辑）。
- 注意：错误文本会透出 `****-key is invalid`（已脱敏）。测试断言不要整串比对。

### R3 · 底座数据全空（P2）

`/api/lessons`、`/api/v2/lessons/library`、`/api/active-words` 均为空结构。页面 200 且 DOM 完整，但**任何「列表非空」断言都会失败**。做有内容的 E2E 前需预置 fixture。

### R4 · `/api/docs` 依赖 CDN（P2）

Swagger UI 的 CSS/JS 指向 `cdn.jsdelivr.net`。离线/内网下页面 200 但白屏。若交付验收含「人工打开 API 文档」，需说明要联网。

### R5 · Whisper 模型只有 large-v3 就绪（P3）

`base`/`medium` 未缓存（`ready=false`）。CET 链路若选 base/medium 会触发下载或失败，**选 large-v3 才稳**。

### R6 · 路径前缀风格不一致（P3）

`/analyze-word`、`/analyze-connected-speech`、`/log-word` 无 `/api` 前缀，其余 AI 接口都有。B 新增 `/api/cet/*` 时保持统一，不要照抄这两个例外。

### R7 · `/api/cet/*` 命名空间干净（信息）

`POST /api/cet/marks`、`/api/cet/anything` 实测均 404，无既有实现、无路由冲突。**B 可安全新建。**

### R8 · 底座句子标记能力可参考但不能直接复用（信息）

`study.py` 提供 `GET/POST /api/sentence-mark(s)`，`db.py` 有 `set_sentence_mark` / `toggle_sentence_mark` / `get_sentence_marks`，表 `sentence_marks` 带 `UNIQUE(lesson_filename, sentence_idx)`，**已完整持久化**。

但键空间是 v1 的 `(filename, sentence_idx)`，与 CET 需要的 `(lesson_id, sentence_id)` 不兼容，且 v1 表与 v2 表族无外键关联。

- 建议 **B**：复用函数形状与幂等写法，键改挂 `lesson_id`/`sentence_id`；**不要直接写 `sentence_marks` 表**，否则 v1/v2 两套 ID 会混淆。
