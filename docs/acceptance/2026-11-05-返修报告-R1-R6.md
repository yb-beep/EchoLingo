### R2 · 409 拒绝了旧步骤，但旧反馈仍污染数据库 ✅ 已修

**根因**（报告判断正确）：`_persist_feedback()` 在校验 `stepId`/`version` **之前**调用，

**修复**：拆出 `_persist_feedback_conn(conn, practice, ...)`，

**实测**（真实 API）：
```

2) 旧步骤 meaning:      HTTP=409  code=STALE_RESPONSE
3) 拒绝后实际状态:      latestFeedback=sound  feedbackHistory=1
   → 状态完全未被污染 ✅
```

## 2. 顺带发现并修的真实缺陷（报告未提，是我修 R2 时暴露的）

**反馈落库时不应 `revision+1`。**

后端 `_new_step()` 用 `revision` 做乐观锁。我在 `_persist_feedback_conn` 里
`revision+1` 后，紧随其后的 `_new_step` 拿着旧 `revision` 对不上，
误判 `STALE_RESPONSE`。

**实测复现**：`sound` 成功后紧接着发 `meaning` → 409 STALE_RESPONSE（连续失败）。

**修复**：反馈落库只更新 `latest_feedback`，不动 `revision`；
幂等性由事件表的唯一 `event_id` 保证。

**修复后实测**：
```
sound:   HTTP=200  latestFeedback=sound
meaning: HTTP=503  code=AI_NOT_CONFIGURED（未配置模型的预期降级）
         latestFeedback=meaning  历史=2 条
```
