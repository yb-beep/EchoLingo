## 3. 句循环的边界处理（主代理要求写明）

- **判定**：`cet-player.js:548` `enforceLoop()`，条件 `now >= end - LOOP_EPSILON`（`LOOP_EPSILON = 0.02`，:450）。
- **回跳动作**：`seekToSeconds(start)` → 走 `window.__ws.seek()`（页面唯一实现），不另建播放状态。
- **锚点**：`S.loopAnchor = {index, start, end}`，在按 L 时用 `sentenceIndexAt(readTime())` 取当前句快照。
  **不能用 `activeSentenceIndex`** —— 越过句尾那一刻它已经指向下一句了，用它会导致循环跑到下一句去。
- **两个驱动源**：
  1. `timeupdate`（`cet-player.js:363`）—— 兜底。浏览器 `timeupdate` 粒度约 250ms，单靠它句尾最多会多播 250ms 下一句开头（实测听感明显）。
  2. `requestAnimationFrame`（`startLoopWatcher()`，:569）—— 主驱动。开着循环时逐帧比对，回跳误差降到一帧（~16ms）。
     后台标签页 rAF 会暂停，所以保留 `timeupdate` 兜底。
- **防抖**：`S.loopGuardUntil = Date.now() + 260`（`LOOP_GUARD_MS`）。seek 会再触发一次 `timeupdate`，
  不设窗会反复 seek 造成抖动。`enforceLoop()` 开头 `if (Date.now() < S.loopGuardUntil) return;`（:551）。
- **暂停时不回跳**：`if (!el || el.paused) return;` —— 用户可能正停在句尾看原文，硬拉回句首很烦。
- **开启时已在句尾之后**：`toggleLoop()` 里若 `now >= anchor.end` 先 `seekToSeconds(anchor.start)`，
  否则「开了却没反应」。
- **无逐句时间轴**：`toggleLoop()` 直接回退 `loopEnabled = false`，不给假承诺。
- **←/→ 切句时**：若循环开着，锚点跟着走到新句（循环的永远是「正在听的那一句」）。

## 8. 踩到的坑（留给后续维护者）

### 8.1 `hidden` 属性被作者 CSS 盖掉（真实 bug，已修）

`cet-workspace.css:60` 有 `.cet-study-bar .cet-study-item { display: inline-flex; }`。
作者样式的优先级**高于** UA 的 `[hidden] { display: none }`，所以给 `.cet-study-item`
只设 `el.hidden = true` 元素**照样显示**（Playwright 的 `is_hidden()` 也判为可见）。

修复：`setShown(el, show)`（`cet-player.js:689`）同时设 `hidden` 属性与行内 `display`。
行内 `display: ''` 会回落到 class 的 `inline-flex`，不残留样式。
P2-3 提示与循环指示都走这个助手。

### 8.2 `timeupdate` 粒度不够做句循环

浏览器 `timeupdate` 约 250ms 一次，句尾最多多播 250ms 下一句开头。
所以主驱动改用 `requestAnimationFrame`，`timeupdate` 只留兜底（后台标签页 rAF 会停）。

### 8.3 句循环不能锚 `activeSentenceIndex`

越过句尾那一刻 `updateActiveByTime()` 已把 `activeSentenceIndex` 推到下一句，
拿它算「回到哪句开头」会循环到下一句去。必须用按 L 时快照的 `S.loopAnchor`。

### 8.4 按钮上的空格是「点击」

`isButtonLike()` 让底座在按钮/链接聚焦时放弃 Space，否则会和浏览器原生
「空格点击按钮」双响应（队友模块 `cet-listening.js:196-201` 踩过同一个坑）。
