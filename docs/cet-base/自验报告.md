## 四、基线失败归属

### 4.1 演进过程（重要，避免误读）

| 阶段 | SHA | 带 `ELT_USER_DB` | **正确口径** | 说明 |
| --- | --- | --- | --- | --- |
| 基线 | `901db90` | 43 failed | **5 failed** / 594 passed | 施工前状态 |
| 中途 | `0d4d6cc` | 41 failed | **3 failed** / 597 passed / 1 error | 加了 conftest 隔离护栏 |
| 当前集成 | `0517cdd` | — | **2 failed** / 709 passed / 28 skipped | 三板块合并后 |

**「41 failed」这个数字是假的**，作废。它由 `ELT_USER_DB` 环境变量造成：

`backend/db.py` 的数据库路径三级解析是 `contextvar → ELT_USER_DB → DB_PATH`，
**环境变量优先级高于模块属性**。而测试普遍用
`monkeypatch.setattr(db, "DB_PATH", tmp_path/"vocab.db")` 隔离 —— 改的是 ③，改不动 ②。
一旦设了 `ELT_USER_DB`，所有测试写进同一个库互相污染。

最小对照实验（同一文件、同一 SHA）：

```bash
ELT_CONFIG_DIR=/tmp/x/config .venv/bin/python -m pytest -q tests/test_vocab_review.py
# → 23 passed
ELT_USER_DB=/tmp/x/a.db ELT_CONFIG_DIR=/tmp/x/config \
  .venv/bin/python -m pytest -q tests/test_vocab_review.py
# → 10 failed, 13 passed
```

**结论：`ELT_USER_DB` 只用于起服务做数据隔离，禁止用于跑 pytest。**
详见 `docs/cet-base/使用与启动.md` §6 与 `docs/cet-base/evidence/baseline-failures.md`。

### 5.2 `test_cet_base_workspace.py` 的运行前提（**验收方必读**）

该文件是**真实浏览器 + 真实音频**测试，必须指向一个**新起的、已导入材料**的服务：

```bash
# 1) 起服务（隔离库）
ELT_USER_DB=/tmp/ws/vocab.db ELT_CONFIG_DIR=/tmp/ws/config ELT_PORT=5183 \
  .venv/bin/python backend/fastapi_server.py &

# 2) 导入材料（必须在服务启动前或同时，且不要删 output/）
ELT_USER_DB=/tmp/ws/vocab.db .venv/bin/python scripts/cet/import_materials.py --all

# 3) 跑测试
ELT_CONFIG_DIR=/tmp/ws/cfg .venv/bin/python -m pytest -q tests/test_cet_base_workspace.py
```

**三个坑（我自验时全踩过）**：

1. **无服务时整组 skip（25 skipped）** —— 这是**正确行为**，不造假失败，但会让全量数字里多 28 skipped。
2. **服务在但 `output/` 被删** —— 音频 404 → seek 断言失败（`actual 0`）。`import_materials.py` 会把音频复制到 `output/v2_assets/cet/`，删了就没了。
3. **端口上有残留旧服务（如别的 worktree 的 5186）** —— 测试会连上它，读到别的库，产生假失败。**跑前先确认 5183 空闲**。

### 5.4 其它

- **未测平台**：Windows / Linux / 移动端。本版本交付本机可运行源码，不做多平台安装包、不做公网部署。
- **无 AI key 场景**已全程验证；有 key 的 AI 词句解释只验证「不阻塞基础学习」，未验证回答质量。
