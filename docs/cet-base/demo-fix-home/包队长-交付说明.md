## 2. C2 · 精听页「本轮已练」第三态

### 2.1 口径来源（为什么不臆造）

工作区 `cet-listening.js` 的 `markState()`：

```js
if (m.confirmedSentenceId) {
  return S.practice && S.practice.markId === m.markId && S.practice.status === 'complete'
    ? 'done' : 'ready';
}
return 'pending';
```

精听页拿不到 `practice.status`（`/api/cet/marks` 只给 `inPractice`）。**权威替代信号**：
`finish_practice()` 在把 practice 置为 `complete` 的**同一事务**里写 `cet_review_items`，
所以「该句存在复习条目」⇔「带练已结束」。精听页用只读接口 `GET /api/cet/review-items` 取这个集合。

### 2.2 改动（`frontend/templates/intensive.html`）

| 位置 | 内容 |
| --- | --- |
| 变量区 | 新增 `cetCompletedSentenceIds`（已完成带练的 sentenceId 集合）、`CET_MARK_STATE_RANK = {pending:0, ready:1, done:2}` |
| `cetMarkState(mark)` | 三态：无 confirmed → `pending`；有 confirmed 且句在完成集合 → `done`；否则 `ready` |
| `cetMarkLabel(state)` | `done` → 「本轮已练」 |
| `loadCetMarks()` | 拉完 `/api/cet/marks` 后 `await loadCetCompletedSentenceIds()` |
| `loadCetCompletedSentenceIds()` | 只读 `GET /api/cet/review-items`，把 `item.sentence.sentenceId` 收进集合；失败静默（退化两态） |
| 同句多条合并 | 取「最靠前」的状态（`CET_MARK_STATE_RANK` 更小的胜），只要有一处没确认就不显示成「本轮已练」 |
| CSS | `.sentence-cet-mark--done`（绿 `#d6eedd` / 文字 `#1c5c33` / 左边框 `#2f8f4e`）——上一轮已存在，本轮真正用上 |

### 2.3 实测（真实服务 + 真实接口造数据）

在 5343 用 API 造出三态各一条（同一 `cet.session.v1`）：

- 标记 A：确认 → 建带练 → `finish` → 应显示「本轮已练」
- 标记 B：确认，未建带练 → 「待练」
- 标记 C：只按 M，未确认 → 「待确认」

页面实测：

```text
[PASS] C2-1 精听页出现「本轮已练」第三态
  [{'text': '卡点 · 本轮已练', 'cls': '...sentence-cet-mark--done'},
   {'text': '卡点 · 待练',     'cls': '...sentence-cet-mark--ready'},
   {'text': '卡点 · 待确认',   'cls': '...sentence-cet-mark--pending'}]
[PASS] C2-2 同时保留待确认/待练
[PASS] C2-3 三态颜色类齐全
```

### 2.4 已知边界

`/api/cet/review-items` 是**全库**列表（不限材料），本页只按 `sentenceId` 匹配，
不会串材料：`sentenceId` 形如 `v2-<lessonId>-<idx>`，跨材料不会同名。
若该接口不可用，退化为两态（不会把「待练」误显示成「本轮已练」）。

## 6. C6 · 无 key 时隐藏 AI 推荐

### 6.1 改动（`intensive.html`）

| 位置 | 内容 |
| --- | --- |
| `cetAiReady` | `null`（未探测）/ `true` / `false` |
| `probeCetAiAvailability()` | 读 `GET /health` 的 `api_keys.AI_API_KEY`（只有 `configured` / `missing`，不含密钥内容）；**通用模式直接返回 true 不探测** |
| `cetApplyAiAvailability()` | `cetAiReady === false` 时隐藏 `#ai-rec-section` 与 `[data-filter="ai-recommended"]`；若当前筛选正是 AI 推荐则退回「全部」；**通用模式直接 return** |
| `renderAiRecPanel()` | `cetAiReady === false` 时清空 `#ai-rec-body`，不渲染生成按钮（双保险） |
| 启动顺序 | 先 `probeCetAiAvailability()` 再 `loadIntensiveStudy()`（避免先渲染按钮再消失） |
| CSS | 新增 `.mode-filter[hidden], .filter-section[hidden] { display:none !important; }` |

### 6.2 为什么需要那条 CSS

`.mode-filter` 是 `display:flex`（作者样式），优先级高于 UA 的 `[hidden]{display:none}`。
**只设 `hidden` 属性按钮照样显示** —— 第一版实测就是「属性 true、元素仍可见」，
被自己的检查抓到（§7 第 2 条）。加 `!important` 后 `hidden=true` 与可见性一致。

### 6.3 实测

