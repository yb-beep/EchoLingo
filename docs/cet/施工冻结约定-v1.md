## 1. 事件完整集合（不是三种，是七种）

`POST /api/cet/practices/{id}/events` 的 `type` 允许：

| 类型 | 类别 | 用途 |
| --- | --- | --- |
| `playback_start` | 播放 | 开始播放 |
| `playback_end` | 播放 | 结束，携带 `activeMs` 计时 |
| `playback_interrupt` | 播放 | 被打断 |
| `visibility` | 业务 | 前后台切换（前端依赖，不能删） |
| `activity_heartbeat` | 业务 | 前台心跳 |
| `feedback` | 业务 | 反馈落库 |
| `transfer_answer` | 业务 | 换句作答（前端依赖，不能删） |

**短名兼容**：`start` / `end` / `interrupt` 作为 `playback_*` 的别名接受
（Mock 与真实后端都要接受），但**新代码发全名**。

**其他一律 422**（如 `pause`）。

**计时字段**：契约名 `activeMs`，兼容读 `playedMs`。

## 2. 状态枚举（两套并存，不得只留一套）

| 场景 | 枚举 |
| --- | --- |
| 练习状态 | `active` / `complete` |
| AI 请求状态 | `idle` / `pending` / `succeeded` / `failed` / `cancelled` / `stale` |
| 复习会话 | `ready` / `active` / `paused` / `complete` |
| 复习条目 | `current` / `pending` / `done` / `skipped` |
| 反馈 | `sound` / `meaning` / `heard` |

**`succeeded` 与 `complete` 是两个不同对象的状态**，不是同一枚举的两种写法。
测试不得混用（AI 请求用 `succeeded`，练习用 `complete`）。

## 4. 幂等（所有入口统一，不得有绕过路径）

**D01 的核心修正**：幂等保护必须覆盖**两种 ID 入口**，不能只在服务端生成 ID 时生效。

| 场景 | 规则 |
| --- | --- |
| 非空 `listeningSessionId` + 服务端生成 ID | 同一 `materialId` + `session` → 只有一条记录 |
| 非空 `listeningSessionId` + **客户端自带 `attemptId`** | **同样受幂等约束**，返回已存在记录的 ID |
| 空 `listeningSessionId` + 不同 `attemptId` | **保留为独立作答**（不合并） |
| 历史已有重复记录 | **不删除**；返回时按 `created_at` 最早一条，并在响应中标注 `conflict: true` |

实现要求：用 `cet_attempt_idem` 映射表做原子占位，**在 `if not attempt_id` 分支之外也执行**。

## 5. AI 生命周期（`stale` 必须显式传）

| 触发 | 目标状态 |
| --- | --- |
| 用户主动取消 | `cancelled` |
| 被新请求/新动作取代 | `stale` |
| 模型失败 | `failed` |
| 模型成功 | `succeeded` |

**`_cancel_pending_ai` 的 `status` 参数默认值必须显式传入**，
不能依赖默认值（当前默认 `cancelled`，但「被取代」场景应为 `stale`）。

迟到响应**不得覆盖** `cancelled` / `failed` / `succeeded` 终态。

## 11. 分支纪律（2026-11-05 事故后新增）

**事故**：主代理切换分支时未检查 HEAD，导致两个提交（508e068、67b11e6）
落进了子代理 B 的分支。已用 cherry-pick 修复，但暴露了协作流程缺陷。

### 强制规则

1. **任何人在主工作区操作前，必须先确认当前分支**：
   ```bash
   git branch --show-current   # 必须是预期分支才继续
   ```
2. **子代理只在 `/tmp/wt-<name>` worktree 里提交**，不在主工作区切分支
3. **主代理合并后立即验证**：
   ```bash
   git checkout codex/cet-listening
   git branch --show-current   # 确认
   git log --oneline -3        # 确认提交在正确位置
   ```
4. **提交前自检**：`git log --oneline -1` 的父提交是否是你期望的分支顶端
5. 发现分支污染时：**不要 force push**，先保全（建临时分支），再报告主代理

## 12. 数据安全事故记录（2026-11-05）

**事故**：`scripts/cet/run_contract_controlled.py` 早期版本没有设置 `ELT_USER_DB`，
`create_app()` 的 lifespan 后台任务走 `db.DB_PATH`（= 日常库 `resources/vocab.db`），
反复运行把 `v2_tags` 的自增序列从 30 推到 2460。

**发现者**：B 板块施工者（主动发现并报告，不是我方自查）

**影响评估**：
- 数据本身**完好**：30 行、id 1–30、无冲突
- 只影响新插入 id 的起点（会从 2461 开始跳跃，但唯一）
- 其他表序列干净（`story_history`/`v2_chat_sessions`/`v2_lesson_words` 都是 0）

**已修复**：
```bash
# 备份
cp resources/vocab.db /tmp/vocab-backup-<ts>.db
# 序列重置到实际最大 id
UPDATE sqlite_sequence SET seq=30 WHERE name='v2_tags';
```
验证：序列 2460 → 30，行数不变。

**根因与防线**：
1. 脚本类工具**必须显式设 `ELT_USER_DB`**，不能依赖默认路径
2. 脚本启动后**自检**「当前库路径 ≠ 日常库路径」，不等就退出
3. B 已实现第 2 条（实测跑完日常库 md5 不变）

**给后续施工者的要求**：
- 任何会写数据库的脚本，开头必须：
  ```python
  os.environ.setdefault("ELT_USER_DB", str(ISOLATED_DB))
  assert "resources/vocab.db" not in os.environ["ELT_USER_DB"], "禁止写日常库"
  ```
- 测试或探针跑完后，检查日常库 md5 是否变化
