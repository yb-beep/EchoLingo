## 三、每条改了什么

### B1 · 375px 下「交卷」按钮超出屏幕

**原因**：`.ws-step-actions` 里包着 `.cet-step-actions`，后者是行内块容器，子按钮 `flex: 0 0 auto` 不收缩也不换行，整行宽度超过了 375px 视口（实测右边界一度到 432px）。

**改法**（`cet-workspace.css:355-369`）：

```css
.ws-step-actions > .cet-step-actions {
  display: flex; flex: 1 1 auto; flex-wrap: wrap;
  align-items: center; gap: 8px; min-width: 0; max-width: 100%;
}
.ws-step-actions .cet-step-actions > .cet-btn,
.ws-step-actions .cet-step-actions > .cet-btn-sm { flex: 0 0 auto; max-width: 100%; }
```

手机端再补 `.ws-step-actions { width: 100% }`（`cet-workspace.css:538-541`），让换行后的按钮有正确的百分比基准。

**验收**：`evidence/ws-375.png` —— 「交卷」是整行绿色按钮，完整落在屏内；四档宽度都没有横向滚动条。

### B2 · 375px 下题目在页面最底部，边听边答要来回滚

**改法**（`cet-workspace.css:469-510`）：`≤768px` 时不再用 grid，改成 flex 纵向流，并用 `order` 给 10 个区块显式排序。

```css
body[data-cet-mode="on"] .main-grid:has(> .ws-step-bar) { display: flex; flex-direction: column; }
body[data-cet-mode="on"] .main-grid:has(> .ws-step-bar) > .watch-column,
body[data-cet-mode="on"] .main-grid:has(> .ws-step-bar) > .side-column { display: contents; }
```

`display: contents` 是为了把两栏容器「拆平」，让 `#ws-step-panel`（在 `side-column` 里）能排到播放器下方：

| order | 区块 |
| --- | --- |
| 0 | 步骤条 `.ws-step-bar` |
| 1 | 播放器 `.video-card` |
| 2 | 工具栏 `.learning-controls` |
| 3 | 学习条 `.cet-study-bar`（交卷 / 今日复习） |
| 4 | 侧栏页签 `.sidebar-workspace-tabs` |
| **5** | **本步骤面板 `#ws-step-panel`** |
| 6 | 原文卡 `.subtitle-card` |
| 7–10 | 阅读阶段 A/B、大纲、AI 伴学 |

**只在 `body[data-cet-mode="on"]` 且 `:has(> .ws-step-bar)` 时生效**，通用模式（`ELT_CET_MODE=0`）完全不受影响。

**一个必须知道的兼容性**：这段依赖 `:has()` 与 `display: contents`，需要 Chrome/Edge ≥105、Safari ≥15.4、Firefox ≥121。更老的浏览器会**静默退回原来的 grid 顺序**（不是布局崩坏），只是题目回到下方。

**验收**：`evidence/ws-375.png`、`evidence/ws-768.png` —— 两档都是「播放器 → 工具栏 → 交卷 → 本步骤面板 → 原文」。

### B3 · 「当前句 1 / 35」与顶部「32 句」不一致

**根因**：两个数组本来就不是一回事——

| 数组 | 含义 | 四级样例条数 |
| --- | --- | --- |
| `segments` | 原始字幕段（`segments` 表原样） | 32 |
| `sentenceUnits` | 逐句时间轴（`data.sentence_units`，由 `buildSentenceUnits(segments)` 兜底生成） | 35 |

播放定位、「当前句 x/y」、大纲、`__ws.sentences` **全部**走 `sentenceUnits`；只有顶部状态徽标用了 `segments.length`。一段字幕被切成多句时，两者就会差 3。

**改法**（`workspace.html:3126-3134`）：

```js
const hasTranscript = Array.isArray(segments) && segments.length > 0;
// segments 是原始字幕段；sentenceUnits 才是播放与「当前句」共用的逐句时间轴。
const sentenceCount = sentenceUnits.length || segments.length;
const cetLabels = {
  ready: hasTranscript ? `原文就绪 · ${sentenceCount} 句` : '原文就绪',
  unavailable: hasTranscript ? `原文就绪 · ${sentenceCount} 句` : '暂无逐句定位',
};
```

**只说事实**：我没有改 `sentence_units` 的生成逻辑，也没有动数据。35 vs 32 那个差异本身是「一段字幕拆多句」，属于数据侧设计，不在本轮范围。本轮只保证**显示口径统一**：徽标与「当前句 x/y」现在取同一个数组，数学上必然相等。

**验收**：`evidence/ws-1440.png` 顶部「原文就绪 · 32 句」与「当前句 1 / 32」一致（这份是六级材料，两个数组恰好都是 32）。四级样例（35 vs 32）那台机器上只有六级音视频素材，**没有截图复现**，靠上面的同源论证。

### B4 · 1440 下工作区左栏下方大片空白

**改法**（`cet-workspace.css:463-467`）：

```css
@media (min-width: 1101px) {
  body[data-cet-mode="on"]:has(#ws-step-panel) .watch-column .subtitle-card { flex: 1 1 auto; }
```

**效果与一句实话**：左栏的原文卡现在撑满整列，两栏底部对齐（`evidence/ws-1440.png`）。但盲听模式下原文本来就遮住了（只显示「原文已隐藏（听力模式）」），所以画面里**看起来还是白的**——白在卡片内部，不是卡片下方漏底。这是模式本身的语义，不是布局缺陷。如果你觉得「一个巨大的空卡片」比「卡片下方留白」更难看，把这一条单独 revert 掉即可（一个 `@media` 块，无其他依赖）。

### 5.1 关于 passed / skipped 数字与队长那份不一样

| 跑在哪 | failed | passed | skipped |
| --- | --- | --- | --- |
| 队长（macOS，`codex/demo-fix-home`） | 2 | 1069 | 104 |
| 我这边（Windows，`codex/demo-fix-ws`） | 2 | **1049** | **124** |

差的正好是 20 个：pass 少 20，skip 多 20。**这不是本轮改动造成的**，理由有两条：

1. skip 与否由 `skipif` 标记（依赖、平台、可选工具）在**收集阶段**决定，本轮只改了「1 个 CSS 文件 + 模板里 1 处句数表达式」，不可能让 20 个用例从 pass 变成 skip；
2. 这两个数字是施工方和我各自独立跑出来的同一结果（`1049 / 124`），在 Windows 上稳定复现。

**结论**：这是 macOS ↔ Windows 的依赖差异（本机缺部分可选组件，用例自动转 skip）。**failed 仍是 2，未增加**，满足「全量回归 failed 不能超过 2」的验收线。如果你要求两边数字完全对齐，请以你那台 macOS 上的重跑为准；需要我在本机再跑一遍基线 `5d4a1e0` 做同机对比，说一声（约 12 分钟）。
