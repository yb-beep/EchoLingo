## 5. P5-4 · 正式库快照脚本备选写法

### 复现与定位

`resources/vocab.db` 的 `pragma journal_mode` 实测为 **`wal`**。WAL 库用只读 URI 打开时，
仍需在同目录创建/映射 `-shm`/`-wal`，目录不可写就会失败。本机复现到两条：

```
sqlite3.OperationalError: unable to open database file
sqlite3.OperationalError: attempt to write a readonly database     ← WAL + 目录不可写，已复现
```

### 补的备选写法（§5.1.1，可直接复制运行）

```python
def logical_snapshot(path):
    tmpdir = tempfile.mkdtemp(prefix="db-snapshot-")
    dst = os.path.join(tmpdir, "vocab.db")
    shutil.copy2(path, dst)        # 只做 cp：源文件只读操作，不打开、不写源库
    try:
        con = sqlite3.connect(dst) # 普通打开副本
        ...
    finally:
        shutil.rmtree(tmpdir, ignore_errors=True)
```

### 实测：两方案结果完全相同（从文档里抽出代码块原样执行）

```
方案 A（mode=ro）  : 92b86dbaceb711b0a244d6e0b447d8fdb042c9c905dfae0894c095f24a3f9dc4
方案 B（cp 后备选）: 92b86dbaceb711b0a244d6e0b447d8fdb042c9c905dfae0894c095f24a3f9dc4
两方案逐表哈希完全相同: True
与文档基线一致: True
```

**源库未被写**：`cp` 前后 `resources/vocab.db` md5 都是 `55a7cb25573e388a986f86866e9671dd`
（主检出与 worktree 两份副本 md5 相同）。全程没有对源库执行 `sqlite3.connect`。
