### C2 · 精听页补「本轮已练」第三态

**问题**：精听页只有「待确认 / 待练」，工作区有三态，对不上。

**为什么原来做不了**：`/api/cet/marks` 只返回 `inPractice`（带练是否被占用），不返回 `practice.status`。

**怎么解决的**：`finish_practice()` 在把 practice 置为 `complete` 的**同一事务**里写 `cet_review_items`，
所以「该句存在复习条目」⇔「带练已结束」。精听页用只读接口 `GET /api/cet/review-items` 取这个集合，
`cetMarkState()` 改成三态：

```js
无 confirmedSentenceId                  → pending（待确认）
有 confirmed + 句在完成集合             → done（本轮已练）
有 confirmed + 句不在完成集合           → ready（待练）
```

同句多条标记时取「最靠前」的状态：只要还有一处没确认，就不显示成「本轮已练」。

**实测**（真实服务 + API 造三态数据）：

```text
[PASS] C2-1 精听页出现「本轮已练」第三态
  [{'text': '卡点 · 本轮已练', 'cls': '...sentence-cet-mark--done'},
   {'text': '卡点 · 待练',     'cls': '...sentence-cet-mark--ready'},
   {'text': '卡点 · 待确认',   'cls': '...sentence-cet-mark--pending'}]
[PASS] C2-2 同时保留待确认/待练
[PASS] C2-3 三态颜色类齐全
```

**边界**：`/api/cet/review-items` 不可用时退化为两态（不会把「待练」误显示成「本轮已练」）。
「本轮已练」不区分具体哪一轮 —— 该句历史上完成过带练就显示（工作区同口径）。

### C6 · 无 key 时隐藏 AI 推荐

**改法**：

- `probeCetAiAvailability()`：读 `GET /health` 的 `api_keys.AI_API_KEY`（只有 `configured` / `missing`，不含密钥内容）；
- `cetApplyAiAvailability()`：`missing` 时隐藏 `#ai-rec-section` 与 `[data-filter="ai-recommended"]`，当前筛选是 AI 推荐则退回「全部」；
- `renderAiRecPanel()`：再兜一层，不渲染生成按钮（不留「按钮在、点了没结果」的死入口）；
- 启动顺序：先探测再加载内容，避免先渲染按钮再消失；
- **通用模式直接跳过**（`if (!CET_ON) return`），保证 `ELT_CET_MODE=0` 与基线一致。

**为什么还要加一条 CSS**：`.mode-filter` 是 `display:flex`（作者样式），优先级高于 UA 的
`[hidden]{display:none}` —— **只设 `hidden` 属性按钮照样显示**。第一版实测就是「属性 true、元素仍可见」，
被自己的检查抓到。补 `.mode-filter[hidden], .filter-section[hidden] { display:none !important; }`。

**实测**：

```text

   → {'health':'missing','sectionHidden':True,'sectionVisible':False,'btnExists':False,'filterHidden':True}
```
