## 二、`/api/vocab-review/activate` 确切签名（供包1 对齐）

已按源码核对，不是猜测：

**路由**：`backend/webapp/fastapi_routes/vocab.py:272`（`POST /api/vocab-review/activate`）
**Body 定义**：同文件 `:59` `class ActivateReviewWordBody`

```python
class ActivateReviewWordBody(BaseModel):
    word: Optional[str] = None          # 或 target（二选一，都不给 → 400 word required）
    target: Optional[str] = None
    source: str = "manual"              # 允许: manual/reading/listening/intensive/sentence_library/story
    lesson_id: Optional[int] = None
    meaning: str = ""
    target_type: str = "word"           # word | phrase
    lemma: str = ""
    display_text: str = ""
```

**返回**：`{**item, "in_review_book": true}`

**两条硬约束（实测确认）**：
1. `source` 传 `lookup` / `practice` → **400** `{"error": "explicit collection source required"}`。
   其他未知值不报错，会被**静默降级为 `manual`**（`vocab.py:279-282`）。→ 用 `"listening"`。
2. **幂等**：`db.activate_word_review`（`backend/db.py:1040`）是
   `INSERT ... ON CONFLICT(word) DO UPDATE`，且 `words.count` 有
   `CASE WHEN words.count < 1 THEN 1 ELSE words.count END` 保护。
   → 重复调用**不会重复计数**，这是 P4-1 选「加载时自动补一次」的安全前提（已实测：连调两次，第二次 `synced=0`）。

**包1 请用的 payload 形状**（与我首页侧补同步一致）：
```json
{"word": "hope", "source": "listening", "lesson_id": 2, "meaning": "希望；信心"}
```

## 四、P4-1 设计决策与理由

### 4.1 为什么选「加载时自动补一次」而不是「同步本课收藏」按钮

| 维度 | 加载时自动补（**已采用**） | 同步按钮 |
| --- | --- | --- |
| 痛点匹配 | 任务书原话是「用户无法理解为什么收藏了却在『我的收藏』里看不到」——自动补直接消因 | 把内部数据分叉的认知负担转嫁给用户 |
| 安全性 | 端点幂等（已实测），重复调无副作用 | 同 |
| 代价 | 每次进收藏页一次轻量 POST；端点只处理差集，正常返回 0 | 用户可能永远不点，问题仍在 |
| 可测性 | 浏览器一打开就验证到 | 要多一步点击 |

### 4.2 幂等的三重依据

1. **SQL 层**：`db.activate_word_review` 用 `INSERT ... ON CONFLICT(word) DO UPDATE`；
   `words.count = CASE WHEN words.count < 1 THEN 1 ELSE words.count END` —— 不累加。
2. **差集层**：端点只处理 `v2_lesson_words` 里**不在** `word_review_items` 的词
   （`db.get_review_word_set()` 差集），第二次调用候选集为空。
3. **实测**：连调两次 → `{"synced": 2}` 然后 `{"synced": 0, "words": []}`。

### 4.3 原句回填（发现并修掉一个真实缺口）

`db.get_review_words` 对没有 `contexts` 行的词会回填 `v2_lesson_words` 的课程句。
但实测发现 **`hope` 这类短词的 `v2_lesson_words.sentence` 可能是空的** ——
根因：`db.sentence_contains_word`（`db.py:1283`）对 **<5 字符的词不做词干匹配**
（`if len(w) < 5: return False`），所以 `hope` vs `hoping` 判不中，工作区收藏时把句子丢了。

**处理**（在 `vocab.py`，我的名下文件内解决，不动 `db.py`）：
`sync-collections` 对 `sentence` 为空的词，用 `_first_segment_with_word()` 从字幕段
找真实原句，并显式 `db.add_context()` 写一条 contexts。
→ 实测 `hope` 现在拿到 `Did you notice any sentences with hope or wish?`（含 audio 时间轴），
「← 返回原句」链接正常生成。

> ⚠️ **给主代理的报告**：`db.sentence_contains_word` 的 <5 字符限制是**上游根因**，
> 影响面比「我的收藏」更大（工作区收藏时就丢原句）。`db.py` 不在任何包名下，
> 我没有改。建议列入下一轮，或由包1 在收藏侧调 `db.find_v2_sentence_containing` 兜底。

### 4.4 句子侧不需要补同步

工作区收藏句子写 `v2_phase_b_sentences`，而 `db.list_v2_saved_sentences`（`db.py:2005`）
的 WHERE 条件已包含 `EXISTS v2_phase_b_sentences` —— 句子收藏本来就直连，没有缺口。
所以补同步只处理词侧。

## 五、P4-2 一处有意偏离任务书原文（请审核方注意）

任务书 P4-2 的示例文案是「继续词汇练习 →」，我实际给 CET 模式的是 **「继续自评熟悉度 →」**。

**理由**：该页真实动作是**自评熟悉度三级**（不认识 / 模糊 / 认识，见词卡
`assessWord(...)` 按钮），页面上**没有任何「练习」功能入口**。写「继续词汇练习」
会指向一个不存在的动作，属误导。任务书 P4-2 的核心要求是
「CET 模式下改为中文四六级口径（**经 `cet_copy` 取，别写死**）」，
本改动满足「中文四六级口径 + 走 cet_copy」，**不是漏改，是有意判断**。

通用模式仍保留「继续词汇练习 →」原文，`ELT_CET_MODE=0` 渲染不变。

## 六、P4-3 处理方式

| 脚本 | 处理 | 理由 |
| --- | --- | --- |
| `elt_credits.js` | `{% if cet_features.credits_account %}` → **CET 不输出** | 积分/账号已收束（`credits_account=False`）。裸删会让 18 处 `billableFetch` 调用 ReferenceError，所以配 `billableFetch()` 薄封装 |
| `natural-tts.js` | `{% if cet_features.word_favorites or cet_features.sentence_favorites %}` → **CET 仍输出** | 它是**保留功能直接使用**的：收藏词卡 🔊 发音（`speakWord`）、句子收藏兜底朗读、词汇例句朗读。任务书 P1-6/P4-3 的规则是「按对应 feature 条件加载」，不是「删掉」 |
| `voice-input.js` | **不涉及** | `index.html` 本来就没引它（只有 `workspace.html:1905` 引），P4-3 在 index.html 侧只管两个脚本 |

**`billableFetch()` 薄封装行为**：
- 有 `eltCredits`（通用模式 / 显式开 `credits_account`）→ **完全等价转发**，含 Idempotency-Key、402/409 结构化错误处理；
- 无 `eltCredits`（CET）→ 退化为普通 `fetch`，**仍自动带 Idempotency-Key**（多用户/云端计费激活时缺 key 会被后端 400）；
- 函数名故意取 `billableFetch`（不是 `cetBillableFetch`）：`tests/test_baidu_pan.py:396`
  断言 `html.count("billableFetch('reading_tts', '/api/v2/lessons/start'") >= 2`，
  保留同名可让这条既有契约继续成立，无需改别人的测试。
