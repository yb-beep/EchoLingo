## 3. 这是什么

EchoLingo（开源本地英语学习工具）的**四六级听力专用化**改造。

只做**底座**，不含队友的卡点定位 / AI 带练 / 换句检验 / 智能复习链路。

用户主线：

```
选四级/六级 → 看已有材料或导入本地音频 → 听力工作区
→ 播放 / 拖动 / 倍速 / 逐句回听 → 看原文、查词、收藏
→ 返回材料库 → 再次进入恢复学习位置
```

**这条链路在无 AI key、未接队友模块时独立可用。**

> **「循环」口径更正（返修2 P5-5）**
>
> 上一版本此处把「循环」列进了这条主线，**与实测不符**：
> CET 模式的工作区 `workspace.html` 与底座快捷键 `cet-player.js` 都**没有句循环实现**；
> 唯一带 🔁 循环的是原版「逐句精听」页 `intensive.html`，但它在 CET 模式下
> 当时**全站无可见入口**（返修2 包1 P1-1 正在补）。所以循环此前对用户不可达。
> 已从主线里去掉，改为如实描述。
>
> **待补**：句循环由返修2 包1（P1-1 精听页入口 + 页面自带 🔁）/ 包2（P2-1 `L` 键句循环）补齐，

## 6. 审核建议关注点

### 6.1 队友模块默认关闭（有意设计）

由 `backend/webapp/cet_mode.py` 的 `cet_listening_agent` 控制，默认 `False`。

原因：验收方实测发现底座此前**无条件加载**队友资产，导致新导入的**无题材料**
也出现「开始卡点练习 / 今日复习 / 未交卷 / 交卷」等**点了没反应的假入口**（BASE-05）。

开启方式（二选一，模板不用改）：

```bash
# A. 环境变量（验证用）
ELT_CET_FEATURE_CET_LISTENING_AGENT=1 ... backend/fastapi_server.py

# B. 改常量（正式接入）
# cet_mode.py 里 "cet_listening_agent": {"kept": True}
```

**关闭态判定**：`cet-listening.js` **根本不在 DOM**，不是 CSS 遮挡，
也不是测试里用 Playwright `route.abort()` 拦请求（验收方明确指出后者不算关闭机制）。

### 6.2 测试口径陷阱（最容易踩）

```bash
# ✅ 正确：跑 pytest 只设 ELT_CONFIG_DIR 指向空目录
ELT_CONFIG_DIR=/tmp/x .venv/bin/python -m pytest -q \
  --ignore=tests/test_cet_listening_ui.py --ignore=tests/test_cet_contract.py

# ❌ 错误：用 ELT_USER_DB 跑 pytest
ELT_USER_DB=/tmp/x.db .venv/bin/python -m pytest -q
```

原因：`db.current_db_path()` 优先级是 `contextvar → ELT_USER_DB → DB_PATH`，
env 高于测试的 `monkeypatch.setattr(db, "DB_PATH", ...)`，静默覆盖隔离
→ 所有测试写进同一个库互相污染（表现为几十个无关用例集体失败）。

`ELT_USER_DB` **只用于起服务**做数据隔离。

### 6.3 浏览器测试需真实服务

| 测试文件 | 环境变量 | 不设的后果 |
| --- | --- | --- |
| `test_cet_base_workspace.py` | `CET_BASE_URL`（必填） | 整组 skip（正确行为） |
| `test_cet_listening_ui.py` | `CET_UI_BASE`（**必填**，返修2 P5-1 起不再有默认值） | 整组 skip |

**必须指向本轮新起的服务 + 新库**，指向残留旧实例会因库里已有旧进度导致假失败。

> **返修2 P5-1 口径变更（重要）**：`test_cet_listening_ui.py` 过去默认连
> `http://127.0.0.1:5173`，即演示实例（库 `/tmp/cet-demo`）。任何人直接跑全量 pytest
> 都会把真实的空格标记与进度写入**演示库**，污染演示现场。
> 现在该文件的 `BASE` 默认值改为空字符串，`_service_up()` 在 `BASE` 为空时直接返回
> `False` → 整组 skip，**绝不隐式连任何实例**（与 `test_cet_base_workspace.py` 的
> `CET_BASE_URL` 同一纪律）。
>
> 实测：不设 `CET_UI_BASE` 跑该文件 → `36 skipped`，且 `/tmp/cet-demo/server.log`
> 前后 md5 完全一致（`1a2f353d…`，346 行 / 25453 字节），证明 5173 零新请求。

### 6.4 已排除在口径外的两个测试文件

| 文件 | 原因 |
| --- | --- |
| `test_cet_contract.py` | 连 5199 的共享 Mock，Mock 按进程状态累积，同一代码连跑三次结果不同（2/2/0 失败） |
| `test_cet_listening_ui.py` | 队友模块自己的浏览器测试，需真实服务；**且 `CET_UI_BASE` 已改必填（返修2 P5-1）**，不设即整组 skip，不会误连 5173 演示实例 |

### 6.5 正式库未被污染

本轮所有验证用隔离库。正式库 `resources/vocab.db` 的**只读逻辑快照**
（每表行内容 sha256 + 汇总 digest）在全量回归前后**完全一致**。

> 注意：不能用「行数相同」或「md5 相同」证明。实测反例——
> 只 `UPDATE` 一行不改行数时行数判据失效；WAL 模式下仅打开不写数据 md5 也会变。
> 详见 [正式库隔离说明](./正式库隔离说明.md) §5。
